## 1. 결정

### D37-1 — 확대는 **패널 스코프**다. 전역 토큰(`--fs-1~6`)에 손대지 않는다

35가 만든 `--fs-1~6`은 소방계획서 서식 화면 **전체**의 실값이고 `@media print`가 되돌리는
목록과 한 쌍이다. 여기를 올리면 이미 만족스러운 1.1~3장·목차까지 함께 흔들리고,
`test-plan-readability`의 S0 고정 기준선(픽셀 불변 증명)을 통째로 다시 떠야 한다.

대신 **배율만 패널 서브트리에서 한 단계 올린다**. 되돌리기는 CSS 한 줄이다.

### D37-2 — `--fs-step`은 `--fs-scale`의 사본이다 (변수 순환 회피)

부스트를 이렇게 쓰면 **안 된다**:

```css
[data-fs-boost] { --fs-scale: calc(var(--fs-scale) * 1.15) }   /* ✗ 순환 */
```

CSS 커스텀 프로퍼티가 자기 자신을 참조하면 **guaranteed-invalid**가 되어 값이 통째로 죽고,
글자가 상속 기본값으로 떨어진다. 조용한 전멸이다. 그래서 읽을 이름을 하나 더 둔다.

```css
html[data-fs="lg"] { --fs-scale: 1.15; --fs-step: 1.15 }
html[data-fs="xl"] { --fs-scale: 1.3;  --fs-step: 1.3 }
[data-fs-boost]    { --fs-scale: calc(var(--fs-step) * 1.15) }
```

사본이라 어긋날 수 있으므로 `test-font-scale`이 **두 값을 대조한다**(B-6).
그리고 `--fs-scale`을 각 규칙에서 **먼저** 쓴다 — `test-font-scale.mts:50`이 `{` 바로 뒤를
정규식으로 읽기 때문이다. 순서를 바꾸면 배율 검사가 조용히 `undefined`를 본다.

### D37-3 — 폭은 글자와 **같은 수**로 커진다

35가 세운 불변식이다(`plan-form14.tsx` 패널 주석): 숫자열 폭(`--fs-col-num`)이 배율과 함께
넓어지므로, 글자만 키우고 폭을 고정하면 표가 패널을 넘겨 가로 스크롤이 생긴다.

그래서 폭도 **부스트된** `--fs-scale`을 곱한다. 패널 요소가 `data-fs-boost`를 직접 갖고 있으므로
그 요소 자신의 `width` 선언에서도 부스트된 값이 풀린다.

```css
[data-spec-panel]            { --fs-panel-w: 900px }
[data-spec-panel][data-wide] { --fs-panel-w: 1400px }
```
```
w-[min(96vw, calc(var(--fs-panel-w) * var(--fs-scale)))]
```

**실측 폭** (1920px 화면):

| 배율 | 기본 (900px) | [넓게] (1400px) |
|---|---|---|
| 보통 md | 640 → **1035px** (실측 확인) | 1610px |
| 크게 lg | 736 → 1190px | 1843px (96vw 상한) |
| 아주 크게 xl | 832 → 1345px | 1843px (96vw 상한) |

> 기본이 900이 아니라 1035인 것은 글자가 15% 커진 만큼 폭이 따라간 결과다.
> 너무 넓으면 `--fs-panel-w: 780px`로 내리면 보통 배율에서 ~897px — globals.css 한 줄이다.

96vw 상한은 유지한다. 좁은 화면에서 화면을 통째로 덮으면 뒤 본문 맥락이 사라진다.

### D37-4 — 인쇄는 부스트도 되돌린다 (D35-5 연장)

법정 서식은 규격이라 글자가 커지면 칸을 넘친다. `@media print`에서 **`--fs-scale`을 직접**
되돌려야 한다 — `--fs-step: 1`만으로는 `[data-fs-boost]`가 여전히 ×1.15를 곱해 결과가 1.15다.

```css
@media print {
  :root, html[data-fs] { --fs-scale: 1; --fs-step: 1; … }
  [data-fs-boost] { --fs-scale: 1 }     /* ← 명시도가 같으므로 소스 순서가 뒤여야 이긴다 */
}
```

이 규칙을 위로 옮기면 조용히 무력해진다. 주석과 검사(B-7)로 함께 못 박았다.

### D37-5 — [넓게] 선택은 localStorage다 (DB 아님)

글자 배율(`profiles.form_font_scale`, 마이그레이션 154)과 달리 **기기별 취향**이다.
27인치 데스크톱에서 [넓게]를 골랐다고 노트북까지 따라갈 이유가 없다. 마이그레이션 0건.

⚠ 초기값에서 `localStorage`를 읽으면 서버 렌더에 없어 하이드레이션이 어긋난다.
첫 렌더는 항상 `false`, 마운트 뒤 한 번 교정한다.

## 4. 내가 틀린 것 두 가지 — 검사가 잡았다

설계 단계의 두 전제가 **실행에서 뒤집혔다**. 다음 사람이 같은 착각을 하지 않도록 남긴다.

### 오판 1 — "`:root{--fs-scale:1!important}`가 부스트를 누른다"

**틀렸다.** `!important`는 그 선언이 **이긴 요소**(`<html>`)에서만 힘을 쓴다. 자식은 그 값을
**상속**할 뿐이고, 상속값은 그 자식에 **직접 매칭되는** 선언(`[data-fs-boost]`)에 진다 —
중요도와 무관하게 상속이 먼저 탈락한다.

→ 항등 축이 실제로 깨졌다. 1.4·1.4-specs 두 화면에 12.65 / 13.8 / 14.95 / 16.1 / 17.25px
(= 구 값 × 1.15)가 나타났다. 조상 요소에 `!important`를 걸어 자손을 통제할 수 없다.

### 오판 2 — "`--identity`가 `OLD_VALUES`를 주입한다"

**틀렸다.** `OLD_VALUES`는 `--print` 축 전용이다(`:306`). `--identity`는 **라이브 화면을 수집해
커밋된 고정 기준선(`scripts/_fixtures/35-baseline.json`)과 대조**한다. 그래서 `OLD_VALUES`만
고쳤을 때 실패 수치가 **한 자도 안 변했다** — 그 사실이 오판의 증거였다.

→ 수정: 수집 루프와 1.4-specs 수집 직전에 `BOOST_OFF`를 주입(`:413`, `:443`).
`--overflow`에는 걸지 않는다(거기선 실제로 커진 기하를 재야 넘침이 의미가 있다).
`--baseline`에는 **함께** 건다 — 기록 때 안 걸고 대조 때만 걸면 기준선을 다시 뜨는 순간
항등 축이 통째로 빨개진다.

> ⭐ 이 구조는 항등 주장을 **더 강하게** 만든다: "패널이 변한 이유는 배율 변수 한 개뿐이고,
> 그 한 개를 되돌리면 옛 픽셀과 완전히 같다." 패널 안 `text-form-*` 클래스를 실수로 바꾸면
> (예: `text-form-xs` → `text-form-sm`) 부스트를 눌러도 히스토그램이 어긋나 여전히 잡힌다.
