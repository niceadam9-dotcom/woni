## 3. 🚨 이 변경의 값 — 이 문서의 중심

`activeStepNums`는 **화면 분모가 아니다.** 거기서 ④를 빼면 두 가지가 함께 일어난다.

1. **별지 9호를 한 번도 안 낸 점검이 ①②③만으로 `completed`로 굳는다.**
   `syncInspectionSteps`가 `allActiveDone`을 그 배열로 만들고, 점검 상세를 **여는 것만으로** 발화한다.
   D34-2(「근거 없는 완료를 없앤다 — 하지 않은 일이 소방서 제출 이력에 완료로 남는다」)가 막으려던 자리다.
2. **마감 알림 크론이 ④를 유효 단계에서 빼 법정 15일 보고 알림이 꺼진다.**
   별지 9호(자체점검 실시결과 보고서)는 **불량 유무와 무관한 의무**다(시행규칙 제23조제2항).

사용자가 요청한 것은 **「달력에서 조회가 안 되게」 = 표시**다.
→ **표시 축을 새로 만들고 의무 축(`activeStepNums`)은 한 글자도 건드리지 않는다.**

### 3-1. 받아들이는 대가 (수리하지 않는다 — 명시한다)

- ④ 미제출인데 달력·목록 진행률이 **3/3 100%**로 보인다. 「거짓 초록」의 한 형태다.
  다만 **DB는 `completed`로 가지 않으므로** 이력에 거짓이 남지는 않는다 — 그것이 축을 가른 이유다.
- 사이드바 뱃지·개인 일정 달력에서도 ④가 빠지면, 불량 0건 회차의 별지 9호 경보는
  **크론 알림(종)과 [별지서식] 탭만** 남는다. 되돌리려면 그 두 줄을 `isStepActive`로 돌리면 된다.

## 4. 설계

### 4-1. 표시 축 신설 — `erp/src/lib/inspection-step-status.ts`

`activeStepNums` **아래에 형제 함수**를 만든다. 기존 함수는 **한 글자도 고치지 않는다** —
그 시그니처를 고정하는 단언이 `test-inspection-steps-sync` 12곳 + `_judge2-r4-mutant` 9곳에 있고,
그것들이 **의무 축이 안 움직였다는 증거**가 된다.

```ts
/** 화면에 **그릴** 단계 — activeStepNums와 갈라지는 유일한 지점은 ④다.
 *  ⚠ 완료 판정·알림에 쓰지 말 것. 별지 9호는 불량 유무와 무관한 법정 의무라,
 *  의무 축에서 지우면 sync가 completed를 써 버린다(§3). */
export function visibleStepNums(isSpecial: boolean, needsRepairSteps: boolean): StepNum[] {
  if (!isSpecial) return [1]
  return needsRepairSteps ? [1, 2, 3, 4, 5, 6] : [1, 2, 3]
}
```

> 🚨 **정정(구현판)** — 위 초안은 **독립 리터럴**이라 의무 축이 바뀌면 조용히 갈라진다.
> 실제로는 **파생**으로 구현했다 — `visible ⊆ active`가 값이 아니라 **구조**로 보장된다:
> ```ts
> return activeStepNums(isSpecial, needsRepairSteps).filter(n => needsRepairSteps || n !== 4)
> ```
> ⭐ 이 차이는 **값 단언으로는 안 잡힌다** — 두 판은 네 조합 모두에서 같은 값을 낸다.
> 그래서 초안 형태로 되돌리는 변이(§9-3 변이 ④)를 걸어 실측했고, `_probe-45-neighbors`의
> **구조 단언 2건**이 잡았다. 값 축(`test-inspection-steps-sync`)과 구조 축은 상보적이다.

`NA_CANDIDATE_STEP_NUMS = [5,6]`의 표시용 짝으로 **`NA_DISPLAY_STEP_NUMS = [4,5,6]`**도 발행한다
— 사이드바 뱃지가 count 질의로 **뺄 건수**만 셀 때 쓴다(전 단계를 행으로 받지 않도록).

### 4-2. 조회 계층에 표시 지도 — `erp/src/lib/active-steps.ts`

**추가 질의 0회.** `activeStepsByInspection`이 이미 만든 `needsRepair` 집합을 한 번 더 투영한다.

- `ActiveSteps`에 `visibleMap: Map<string, Set<number>>` 추가
- `isStepVisible(a, id, n)` 신설 — `isStepActive`와 **같은 기울기(모르면 참)**
- `isStepActive` / `isStepNa`는 그대로 — **크론이 계속 쓴다**

> ⭐ 이 모듈이 존재하는 이유가 「순수 함수만 공유하면 부족하다 — **그 함수에 넘길 값을 모으는 일**도
> 공유해야 한다」(45차수 §S11)이므로, 표시 축도 **같은 자리에서** 발행해야 표면이 또 갈라지지 않는다.

## 5. 검사

기존 스위트는 **의무 축이 안 움직였다는 대조군**으로 그대로 둔다.

- `test-inspection-steps-sync.mts` — `activeStepNums` 21단언 **무수정 통과**가 곧 증거.
  `visibleStepNums` 단언 신설: 자체점검×불량0 → `[1,2,3]` / 등록불량 1 → 6개 / `sheetX`만 1 → 6개 /

### 🚨 그 실험이 덤으로 잡은 것 — 공유 E2E 헬퍼의 공허 통과 경로

변이 ③의 첫 시도에서 제품이 아예 안 뜨는데도 스위트가 **초록**이었다. 원인:
`_e2e-helpers.mjs:16` `summary()`가 `process.exit(_fail > 0 ? 1 : 0)`이라,
**셋업 중 예외로 `check()`가 한 번도 안 불리면 「0 통과 / 0 실패」로 exit 0**이다
(`catch`의 `process.exitCode = 1`을 `process.exit`이 덮는다).
→ 이 차수에서는 **내 파일만** 고쳤다(`catch`에서 `check(…, false)`로 실패를 센다).
공유 헬퍼는 수십 개 스위트가 함께 쓰므로 **손대지 않았다** — 고치면 다른 세션의 초록이
붉어질 수 있고, 그 판정은 그쪽 몫이다. **열린 항목으로 남긴다(B-5).**
