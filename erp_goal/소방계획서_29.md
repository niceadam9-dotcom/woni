## 1. 목표와 비목표

- 개인(계정) 단위 테마 선택: 「화이트(현재) / 다크」 2택. 기본값은 화이트 — 기존 사용자는
  아무것도 달라지지 않고, 다크는 opt-in이다.
- 선택은 계정에 저장돼 **기기 간 동기화**된다. 어느 PC에서 로그인해도 내 테마.
- 디자인 톤 = image-18.png: 딥 뉴트럴 다크 배경 + 한 단 밝은 패널, 낮은 채도·부드러운 대비,
  off-white 본문 + 회색 보조 텍스트, 포인트 색(보라)만 살림, 옅은 경계선. 우리 브랜드 보라
  `#7b68ee`가 이 톤에 그대로 어울린다.
- 비목표: '시스템 설정 따름' 옵션(구조만 열어둠, §9) · 모바일 전용 최적화 · 문서/인쇄물의 다크화
  (종이가 정본 — 문서는 항상 라이트다).

## 2. 실측 — 장애물은 하드코딩 hex 하나

인프라는 절반이 이미 있다. Tailwind v4 + shadcn 스캐폴드라 `globals.css:118`에 `.dark` 변수
블록과 `@custom-variant dark (&:is(.dark *))`가 기정의돼 있다. `<html class="dark">`만 붙이면
켜지는 구조다.

그런데 화면이 그 토큰을 안 쓴다 (2026-08-28 실측):

| 항목 | 실측값 |
|---|---|
| 하드코딩 hex 클래스 (`text-[#514b81]` 등) | **6,322곳 / 261파일** |
| `bg-white`·`text-white` | 851곳 / 190파일 |
| `dark:` 변형 사용 | 4곳 (shadcn `ui/button.tsx`뿐) |
| shadcn 시맨틱 토큰(bg-muted 등) 실사용 | 사실상 0 (`bg-background` 1곳 — layout.tsx) |
| 테마 토글 UI·저장 | 없음 |

지금 `.dark`를 켜면 배경만 어두워지고 카드·글자·테두리 전부 라이트 색으로 남아 화면이 깨진다.

**희소식 — 팔레트가 극도로 집중돼 있다.** 상위 9색이 전체의 87%, 상위 30색이면 97%:
`#7b68ee` 1,335 · `#514b81` 1,125 · `#b0acd6` 721 · `#090c1d` 606 · `#d0ccf5` 462 ·
`#c8c4d0` 454 · `#f5f4ff` 379 · `#f8f9fa` 216 · `#e0ddf5` 189. 색의 가짓수가 사실상
토큰 사전 하나 분량이다.

개인 설정 저장 패턴도 이미 있다: `profiles.notification_prefs`(JSONB)를 서버 액션으로 저장
(`settings/actions.ts:26`)하고 설정 페이지가 읽는다 — 테마도 같은 패턴으로 얹는다.

## 3. 심화 실측 — 설계를 바꾼 발견들 (Explore 3에이전트 병렬)

- **`/login`·루트 `layout.tsx`는 정적 렌더다**(cookies() 미사용). 루트 레이아웃에서 쿠키를
  읽으면 정적이 동적으로 전환된다 → 쿠키 판독을 서버가 아니라 인라인 스크립트로 옮긴 이유(D-2).
- **같은 hex가 접두사에 따라 역할이 다르다**: `#090c1d`는 text-(350+)이면서 bg-(~40곳, 역전
  표면 — 어두운 배경에 흰 글자). `#202023`·`#292d34` 카본은 `btn-primary` 배경 — 라이트에서도
  어두운 버튼이라 **다크에서 반전되면 안 된다** → 접두사+hex 쌍으로 치환(D-7).
- **상태색은 공짜로 해결된다**: red ~518 · amber ~217 · green ~200 · blue ~74곳. Tailwind v4는
  `bg-green-50`이 `var(--color-green-50)`을 참조하므로 `.dark`에서 팔레트 변수만 재정의하면
  **컴포넌트 무수정**으로 다크 틴트가 된다(D-8). `*-50` 연한 틴트가 다크에서 불가시해지는
  문제의 정답이 여기 있다.
- **그림자 ~80파일** `shadow-[rgba(...)]` — 다크 배경에서 소실. `@theme`에 이미 있는
  `--shadow-subtle*` 토큰으로 치환 후 `.dark`에서 알파 상향.
- **최악 지점은 react-big-calendar**: `leave-calendar.tsx:92-113`의 `<style>` 태그 80줄이
  라이트 색 하드코딩(`.rbc-*` — 헤더 #f8f9fa·오늘 #f5f4ff·토/공휴일 #dc2626/#2563eb 등).
  클래스 코드모드 밖이라 다크 규칙을 수동 추가해야 한다. `inspection-calendar-client.tsx`도 동류.
- **라이트 고정이 정답인 표면**(의도적 제외): 서명 캔버스(`signature-client.tsx:44`
  ctx.fillStyle 흰색 — 서명은 흰 종이 위 검은 잉크가 정본), 피난도 SVG(`evac-map-builder.tsx`
  fill="#ffffff"), 정적 지도 이미지, 사진.
- **문서·발송 축은 이미 격리돼 있다**: 인쇄 라우트는 전부 PDF/HWP/xlsx 바이너리 응답 또는
  iframe blob 뷰어, 메일은 plain text 발송(HTML 파트 없음), 별지 미리보기는 iframe/srcDoc 격리.
  걱정했던 "인쇄 라우트 강제 light"는 불필요 — **코드모드 제외 목록**(lib/doc-templates·scripts)
  이면 충분하다(D-4).
- **E2E·프로브에 색/클래스 단언 없음** 실측(유일 예외 `_probe-print-no-highlight`는 문서 CSS
  텍스트 상수 단언 — 무관). 클래스 치환이 기존 테스트를 깨지 않는다.
- 모달 백드롭 `bg-black/30~40` ~44파일 — 다크에서도 동작하나 대비 약화. 다크에서 알파 상향(S3).
- 인라인 `style={{...}}` 색 — 코드모드가 못 잡는 축. S3에서 파일 단위 개별 처리.

## 4. 설계 결정

- **D-1 시맨틱 토큰 치환이 정공법**: 6,300곳에 `dark:` 변형 살포는 불가·유지보수 불가.
  `[class*="bg-[#…]"]` 속성 선택자 해킹은 `hover:bg-[#…]`까지 부분일치로 잡아 오작동 — 기각.
- **D-2 저장 = DB 정본 + 쿠키, 클래스 부여 = 인라인 스크립트**:
  - 정본은 `profiles.theme`(`'light'|'dark'`, default `'light'`) — 기기 간 동기화.
  - 쿠키는 첫 페인트용 캐시. 루트 레이아웃은 **cookies()를 읽지 않는다**(정적 유지, §3 실측).
    대신 `<head>` 인라인 스크립트 3줄이 첫 페인트 전에 쿠키를 읽어 `<html>` 클래스를 붙인다
    — FOUC 없음, next-themes 불필요.
  - 동기화 4경로: ①변경 시 서버 액션이 DB+쿠키 기록, 클라이언트가 클래스 즉시 토글
    ②로그인 시 프로필 테마를 쿠키에 세팅 ③로그아웃 시 쿠키 삭제(공용 PC에 남지 않게)
    ④쿠키 유실(새 기기) 시 대시보드 레이아웃의 한 줄짜리 클라이언트 보정.
  - 로그인 화면은 항상 라이트 — 테마는 로그인 후의 개인 설정이다.
- **D-3 기본값 라이트**: 기존 사용자·E2E·스크린샷 프로브 전부 무영향(§3 색 단언 없음 실측).
- **D-4 문서·발송 축은 코드모드 제외 목록으로 지킨다**: `lib/doc-templates/*`·`scripts/` 제외.
  인쇄 라우트·메일·미리보기는 이미 격리(§3). Gotenberg 서버 렌더는 앱 테마와 무관.
- **D-5 설정 화면 2택**: 라디오 「화이트(현재) / 다크」, 저장 버튼 없이 클릭 즉시 적용
  (알림 설정 카드와 같은 서버 액션 패턴). 헤더에 빠른 토글(달/해) 추가.
- **D-6 롤아웃 순서**: 인프라 먼저(설정 카드는 숨김/관리자만) → 토큰 치환 → 팔레트 육안 확인 후
  전 사용자 노출. "만들다 만 다크"가 사용자 눈에 띄는 사고를 막는다.
- **D-7 토큰은 접두사(역할)로 가른다**: 같은 hex라도 `text-[#090c1d]`→`text-ink` vs
  `bg-[#090c1d]`→`bg-inverse`(역전 표면 — 다크에서도 어두운 채 유지), 카본 버튼
  `bg-[#202023]`→`bg-btn-carbon`(고정 토큰, 다크 반전 제외). 코드모드는 hex 단독이 아니라
  **유틸리티 접두사+hex 쌍** 단위로 치환한다. `text-white`는 색 버튼 위 글자라 유지,
  `bg-white`만 `bg-surface`로 간다.
- **D-8 상태색·그림자는 변수 재정의로 해결**: `.dark`에서 `--color-red-50` 등 Tailwind 팔레트
  변수를 재정의 — 상태색 ~1,000곳 컴포넌트 무수정. 그림자는 `--shadow-subtle*` 토큰으로 치환 후
  `.dark`에서 알파 상향.

## 5. 토큰 표 (**구현된 실값** — `globals.css` 정본)

라이트 값은 종전 hex 축자다 — 화이트 모드는 픽셀 단위로 불변이어야 한다(D-3).
⚠ `@theme inline`은 값을 유틸리티에 **인라인**하므로 `.dark` 재정의가 먹지 않는다.
토큰은 `@theme`에서 `var(--t-*)`를 가리키고 실값은 `:root`/`.dark`에 둔다(shadcn `--background` 패턴).

| 토큰 | 역할 | 라이트 | 다크 | 비고 |
|---|---|---|---|---|
| `paper` | 페이지 배경·옅은 면 | #f8f9fa | **#1b1b1e** | 설계의 canvas·surface-hover를 하나로 합쳤다 |
| `surface` | 카드·패널 (`bg-white` 치환) | #ffffff | **#232327** | — |
| `ink` | 본문 강조 텍스트 | #090c1d | #ededf0 | vs surface ≈ 12:1 ✅ AA |
| `ink-strong` | 진한 보조(카본 텍스트) | #292d34 | #d8d8de | `text-[#292d34]` 축 |
| `ink-sub` | 본문 보조 텍스트 | #514b81 | #a8a5c0 | ≈ 7:1 ✅ AA · 최다 사용(1,120곳) |
| `ink-soft` | 약한 보조 | #847ba8 | #8c88a8 | #8b87b8·#7d78a8 흡수 |
| `ink-faint` | 자리표시·희미 | #b0acd6 | #6e6a8a | 장식용 — AA 비대상(라이트도 ≈2.1:1) |
| `brand` | 브랜드 보라 | #7b68ee | #8f7df2 | 다크 가독 위해 한 톤 밝게 |
| `brand-strong` | hover·강조 | #6647f0 | #7f6cf5 | #6a5acd·#6a57dd 등 흡수 |

**치환하지 않은 것**(테마 불변 — 코드모드 화이트리스트): 카본 버튼 `bg-[#202023]`·`bg-[#292d34]`
79곳(라이트에서도 어두운 버튼이라 다크에서 반전하면 안 된다) · 역전 표면 `bg-[#090c1d]` 1곳 ·
`text-white`(색 버튼 위 글자) · `print:` 변형 전부(§10-①).

**상태색**(red/amber/green/blue 등 21팔레트, 2,391곳)은 토큰으로 바꾸지 않았다 — Tailwind v4에서
`bg-red-50`이 `var(--color-red-50)`을 참조하므로 **`.dark`에서 팔레트 변수만 재정의**하면
컴포넌트 무수정으로 따라온다(D-8). 틴트(50~200)는 저휘도 불투명값으로 낮추고 텍스트(400~700)는
밝은 쪽으로 올린다. 투명도 방식은 겹침 표면에서 색이 섞여 기각.

**달력 일정 칩**(`--chip-*` 9쌍)은 인라인 style이라 별도 토큰이다 — §10-③.

### S1 — 개인별 테마 인프라 (마이그레이션 151)

- `151_profile_theme.sql`: `profiles.theme text not null default 'light'` +
  `check (theme in ('light','dark'))`. **스테이징·운영 적용은 각각 별도 승인.**
- 루트 `layout.tsx`: `<head>` 인라인 스크립트(쿠키→클래스, 정적 유지).
- 테마 저장 서버 액션(`settings/actions.ts`에 추가 — notification_prefs와 같은 패턴, DB+쿠키).
- 로그인 액션에 쿠키 세팅 · 로그아웃 액션에 쿠키 삭제 배선.
- 설정 화면 "화면 테마" 카드: 「화이트(현재) / 다크」 2택 라디오, 클릭 즉시 적용.
  롤아웃 전까지 관리자만 노출(D-6). 헤더 빠른 토글.
- E2E: 저장 · 재로그인 유지 · **계정 간 격리**(A 다크 ≠ B 라이트) · 로그아웃 쿠키 제거.

### S2 — 토큰 사전 + 기계 치환

- 상위 30색 × 접두사 조합의 시맨틱 명명 확정(D-7) → `@theme` 등록 + `.dark` 팔레트 1벌(§5).
- 코드모드: ~250파일 결정적 치환. 제외 목록 = `lib/doc-templates/`·`scripts/`(D-4).
  파일별 치환 건수를 로그로 남긴다.
- `bg-white`→`bg-surface`(text-white 유지), globals.css `@layer components`
  (btn-primary·btn-ghost·card-surface) 토큰화.
- **잔여 hex 카운트 게이트**: 제외 목록 밖 hex 0건 목표 — "다 바꿨다"를 카운트로 닫는다.

### S3 — 꼬리 처리

## 10-2. 실결함 4건 — 전부 "기존 검사가 초록인 축" 밖

1. **`print:` 변형까지 토큰으로 치환** — `print:bg-white`가 `print:bg-surface`가 되면
   **다크 사용자의 인쇄물 배경이 어두워진다.** 실제 인쇄 전엔 아무도 모른다.
   복원 + 코드모드에 "`print:` 변형은 치환 금지" 규칙을 못 박았다.
2. **globals.css로 옮긴 rbc 스킨이 라이브러리 CSS에 조용히 졌다** —
   `react-big-calendar.css`는 두 컴포넌트에서 `import`돼 **globals보다 나중에 주입**되므로
   명시도가 같으면 나중 것이 이긴다. 종전 `<style>` 태그는 DOM 렌더 시점 주입이라
   **우연히 이기고 있었을 뿐**이다. 실측으로 셀이 라이브러리 회색(#e6e6e6)·오늘이 하늘색(#eaf6ff)으로
   남아 다크에서 달력만 흰 판이었다. **클래스 중복**(`.rbc-today.rbc-today`)으로 명시도를
   (0,2,0)으로 올려 주입 순서에 의존하지 않게 했다.
3. **일정 칩이 밝게 남았다 — 사용자 지적(`image-19.png`)** ⚠ 내 오판이 원인이다.
   `chipStyle()`·`TYPE_CHIP`이 **인라인 style 리터럴**(흰 바탕 전제 '옅은 배경 + 진한 글자')이라
   코드모드가 닿지 않았는데, S3에서 이를 보고 "자기완결 칩이라 다크에서도 가독"이라며 보류했다.
   실제로는 어두운 달력 위에 흰 블록이 떠 있었다. `--chip-*` 토큰 9쌍을 신설해
   점검 달력(월·주·목록이 `chipStyle` 하나를 공유)·점검확정 달력·**범례 스와치**가 같은 토큰을
   쓰게 했다(범례를 리터럴로 두면 안내와 화면이 다크에서 갈린다).
4. **공휴일 칸도 인라인 style 리터럴**(`dayPropGetter`의 `#fef2f2`) — 두 달력 모두
   `var(--color-red-50)`로. 한쪽만 고치면 다음 판정에서 나머지가 나온다.
