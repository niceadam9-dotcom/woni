## 3. 설계

### S1 — `globals.css`: 기하 토큰 가산 (화면 무변화)

35 체계를 **그대로 재사용**한다. **새 배율 축을 만들지 않는다** — 축이 둘이 되면 `test-font-scale`의 CSS↔TS 단일 원천 검사가 못 덮는 사각이 생긴다.

`:root` 블록 끝(`--fs-col-num` 다음)에:

```css
  /* 점검표 입력(드로어·전용 화면) 기하 — 글자와 **함께** 커져야 하는 치수.
     ⚠ --sheet-hdr-h는 중분류 sticky 높이와 소제목 sticky offset의 **공통 원천**이다.
       둘이 갈라지면 배율 lg/xl에서 두 줄이 겹쳐 항목 첫 행을 가린다
       (종전 h-[22px]/top-[22px] 하드코딩 쌍의 사고 지점). */
  --sheet-hdr-h:  26px;  /* 구 22px — h-6(24px) 칩이 이미 2px 넘치고 있었다 */
  --sheet-chip-h: 24px;  /* 일괄 버튼 — 구 h-6 */
  --sheet-toc-w: 208px;  /* 머더 목차 — 구 lg:w-40(160px) */
```

`@utility h-form-8` 아래에:

```css
/* 점검표 입력 기하 — text-form-*과 같은 소비 방식이라 @media print의 --fs-scale:1이 자동으로 걸린다 */
@utility h-sheet-hdr     { height: calc(var(--sheet-hdr-h)  * var(--fs-scale)); }
@utility top-sheet-hdr   { top:    calc(var(--sheet-hdr-h)  * var(--fs-scale)); }
@utility h-sheet-chip    { height: calc(var(--sheet-chip-h) * var(--fs-scale)); }
@utility w-sheet-toc     { width:  calc(var(--sheet-toc-w)  * var(--fs-scale)); }
@utility size-sheet-mark { width:  calc(40px * var(--fs-scale));
                           height: calc(40px * var(--fs-scale)); }
```

**스코프가 성립하는 이유** — 드로어는 `createPortal(document.body)`(`sheet-drawer.tsx:97,122`)지만, `--fs-scale`은 `html[data-fs]`에 `--sheet-*`는 `:root`(=html)에 선언되므로 `<body>` 하위 포털 노드에 **상속으로** 도달한다. `globals.css:177-179`의 기존 주석이 같은 근거(1.4 `fixed inset-0` 패널)로 `<html>` 스코프를 택한 이유를 이미 적어 뒀다. 계산은 선언 지점이 아니라 **소비 지점**에서 일어나므로 항상 최신 배율로 치환된다.

**인쇄 — 별도 토큰 불필요.** `@media print`(`:223-234`)가 `--fs-scale:1`로 누르므로 `h-sheet-hdr`=26px, `top-sheet-hdr`=26px로 **함께** 되돌아간다. 두 값의 등식이 배율과 무관하게 성립하는 것이 이 설계의 핵심이다.

`test-font-scale.mts`에 코드 축 단언 1개 추가:

```ts
// sticky 2층 겹침 방지 — 두 유틸리티는 **같은 변수**를 읽어야 한다
const hdrH   = css.match(/@utility h-sheet-hdr[^}]*calc\(var\((--[\w-]+)\)/)?.[1]
const subTop = css.match(/@utility top-sheet-hdr[^}]*calc\(var\((--[\w-]+)\)/)?.[1]
check('S-1 h-sheet-hdr와 top-sheet-hdr가 같은 변수 (sticky 겹침 방지)',
  !!hdrH && hdrH === subTop, `hdr=${hdrH} sub=${subTop}`)
```

**`--sheet-hdr-h`를 22 → 26으로 올리는 근거:** 배율 1에서 `h-6`(24px) 칩이 정확히 들어가고 텍스트 13px×1.5=19.5px도 여유가 생긴다. 모든 배율에서 `헤더 26k` vs `칩 24k`의 비가 보존되므로 이 관계는 **배율과 무관하게 항상 성립**한다.

```tsx
  max-sm:inset-x-0 max-sm:top-auto max-sm:bottom-0 max-sm:h-[95dvh] max-sm:rounded-b-none max-sm:border-x-0 max-sm:border-b-0"
```

불변식 4가지:

1. **`absolute`를 `fixed`로 바꾸지 말 것.** 포커스 트랩(`:90`)이 `el.offsetParent !== null`로 거른다. `offsetParent`는 가장 가까운 **positioned 조상**을 찾는데, 패널이 `absolute`인 지금은 자손 전부가 패널을 offsetParent로 갖는다. P9(Tab 20회)가 이 축을 지킨다.
2. **`border-l` → `border`**(사면) + `rounded-2xl`. 오른쪽 앵커가 아니라 떠 있는 카드가 됐으므로 좌측만 선을 긋는 것이 의미를 잃는다.
3. **`overflow-hidden`** — 헤더 border-b와 안쪽 스크롤 박스가 둥근 모서리를 뚫는 것을 막는다. sticky는 안쪽 스크롤 박스 기준이라 영향 없다.
4. **`inset-4` + `max-sm:` 관용구 고수.** Tailwind v4는 단축(`inset-4`)을 longhand(`max-sm:inset-x-0`/`top-auto`/`bottom-0`)보다 **앞에** 배치하므로 `max-sm:`가 이긴다 — 이 파일이 지금 쓰는 형태(`inset-y-0` + `max-sm:top-auto/bottom-0`)와 동일해 검증된 구조다. `sm:` 접두로 뒤집으면(`inset-x-0 bottom-0 sm:inset-4`) unprefixed longhand가 `sm:` 단축을 이겨 **데스크톱이 바텀시트로 고착된다.**

**`max-sm` 바텀시트는 유지한다.** 모바일에서 16px 여백을 남기면 한 손 조작 시 가장자리 탭이 백드롭에 먹힌다. `92vh → 95dvh`로만 올린다(`vh`는 모바일 주소창 때문에 잘리고, 호출부는 이미 `dvh`를 쓰고 있어 단위를 통일).

헤더 제목(`:107`) `text-sm` → `text-form-base`. **닫기 버튼 `size-8`은 고정** — 32px 버튼 + `py-2.5`가 헤더 행 높이를 지배하고, 제목이 xl에서 19.5px(행간 1.4286 → 27.9px)까지 커져도 여전히 버튼보다 낮다. 헤더가 배율에 따라 요동치지 않는다.

바디(`:115-117`) — 🔴 `min-h-0` 추가가 S4의 전제:

```tsx
<div className="flex-1 min-h-0 flex flex-col lg:flex-row gap-3 p-4">
  {toc}
  <div className="flex-1 min-w-0 min-h-0 flex flex-col">{children}</div>
</div>
```

`lg`(row)에서는 교차축 stretch로 자식 높이가 확정되지만, `max-lg`(column)에서는 이 div가 `flex-1`만 갖고 `min-height:auto`라 **콘텐츠 높이 아래로 줄어들지 않는다** → 안쪽 스크롤 박스가 무한히 자라 페이지가 통째로 스크롤된다.

### S3 — 🔴 `test-sheet-mother-drawer.mts` 백드롭 클릭 (S2와 같은 커밋)

`:286`·`:299` 두 줄 모두:

```ts
// 드로어가 전체화면(inset-4)이 되며 백드롭은 16px 테두리만 남았다 — 요소로 집고 코너를 눌러
// inset 값 변화에 면역시킨다
await page.locator('[data-testid="sheet-drawer-backdrop"]').click({ position: { x: 4, y: 4 } })
```

Playwright의 actionability는 (4,4)에서 hit-target을 검사하는데 그 좌표는 패널(x≥16) 밖이라 백드롭이 이벤트를 받는다. 백드롭이 `onMouseDown`을 쓰지만 `.click()`은 mousedown+mouseup을 모두 보내므로 동작한다.

**게이트:** 여기서 스위트를 한 번 돌려 **P3·P5·P8·P9 초록**을 확인한 뒤 S4로 간다.

### S4 — `maxHeight` 매직넘버 제거 (드로어만)

`inspection-sheet-client.tsx:563`:

```diff
-  maxHeight="max-h-[calc(100dvh-260px)] max-sm:max-h-[calc(92dvh-250px)]"
+  // 매직넘버 폐기 — 조상이 전부 flex column이라 남은 공간을 그냥 채우면 된다.
+  // 260px는 '헤더+배너+푸터가 이만큼'이라는 가정이었고, 배율이 헤더를 키우는 순간 틀린다.
+  maxHeight="flex-1 min-h-0"
```

조상 사슬(S2 이후):

```
패널  absolute inset-4 … flex flex-col            ← 높이 확정(inset)
 └ 바디 flex-1 min-h-0 flex flex-col lg:flex-row
    └ 우측 flex-1 min-w-0 min-h-0 flex flex-col   ← S2에서 min-h-0 추가
       └ SheetItemEditor fragment
          ├ body  ← 여기에 flex-1 min-h-0 overflow-y-auto pr-1
          ├ notice <p> mt-2      (auto)
          ├ error  <p> mt-2      (auto)
          └ 버튼행 flex gap-2 mt-3 (auto — 드로어는 hideSave만 걸어 [닫기]가 실제로 렌더된다)
```

형제가 전부 auto 높이라 body가 남는 공간을 가져간다. `overflow-y-auto`는 `maxHeight`와 **별도 문자열**(`sheet-item-editor.tsx:179`의 `` `${maxHeight} overflow-y-auto pr-1` ``)이라 그대로 남는다 → 테스트의 `el.closest('.overflow-y-auto')`(`test-sheet-mother-drawer.mts:111,116`)가 **계속 매치된다**.

`max-sm` 바텀시트도 같은 flex 사슬이라 별도 분기가 불필요하다 — `max-sm:max-h-[calc(92dvh-250px)]`도 함께 사라진다.

**`sheet-entry-client.tsx:430`(전용 입력 페이지)은 바꾸지 않는다.** 그 우측 패널의 조상은 flex column이 아니다:

```
:360  <div className="grid grid-cols-1 lg:grid-cols-[minmax(280px,360px)_1fr] gap-4">
:403    <div className="rounded-xl … p-4 min-h-[320px]">   ← grid item, 높이 미확정
:419      <div ref={scrollBoxRef}>                          ← 일반 div
:430        maxHeight="max-h-[calc(100dvh-360px)]"
```

`flex-1 min-h-0`을 넣으면 flex 컨테이너가 없어 `flex-1`이 무시되고 `min-h-0`만 남아 **박스가 무한히 자라 페이지 전체 스크롤로 퇴화한다**(master-detail의 "좌 목록 상시 노출" 전제가 깨진다).

그리고 그 화면의 **360px은 여전히 옳다** — 박스 위 크롬(`:411` 제목 `text-sm`, `:412` 카운트 `text-xs`, `:415` siblings `text-[11px]`, `:363` 필터 줄)은 `sheet-entry-client` 자신의 클래스이고 **이번 토큰화 대상이 아니라** 배율을 올려도 높이가 변하지 않는다. 커지는 것은 박스 **안쪽**뿐이고 그건 스크롤이 흡수한다. 좌측 목록의 `max-h-[calc(100dvh-260px)]`(`:373`)도 동일 이유로 무변경.

### 4.2 높이 스케일링 결정 근거

- **○/✕ 버튼은 스케일한다** (40→46→52). `sheet-item-editor.tsx:57-58` 주석이 "현장에서 장갑 낀 손으로 누르는 버튼 — 28px는 오탭이 잦아 40px로 키웠다"고 근거를 남겼다. 배율을 올리는 사용자는 정확히 그 오탭이 문제인 층이다. 모든 배율이 ≥1이라 **40px 아래로는 절대 안 내려간다.**
- **일괄 칩도 스케일한다** (24→27.6→31.2). 안 하면 xl에서 15.6px 글자가 24px 상자에 갇힌다(행간 1.5 → 23.4px, 거의 꽉 참).

## 10. 설계 정정 (구현 중 드러난 것)

전문은 `소방계획서_38.json`의 `design_corrections`(F-1~F-11). 값이 큰 것만:

**F-6 — 내 검증 배치가 3.5시간 멈춘 원인은 앱이 아니라 내 스크립트였다.**
PowerShell에서 `$args`는 **자동 변수**라 `$args = $s -split ' '` 대입이 무시됐고, `& npx tsx @args`가 스크립트 인자 없이 실행돼 tsx가 REPL로 stdin을 무한 대기했다. `2>$null`로 stderr까지 버려 단서를 지웠다. → 스플랫 변수명은 `$args`를 피하고, 검사 실행에서 stderr를 버리지 말 것. **0줄 출력이 오래 지속되면 '느린 것'이 아니라 '멈춘 것'을 의심하고 프로세스 커맨드라인을 볼 것.**

**F-7 — 남의 작업이 in-flight일 때 잰 수치는 증거가 못 된다.**
identity 첫 실행은 `[1.1]`까지 3실패였으나 37이 커밋된 뒤 재실행에서 `[1.1]`은 사라졌다. 처음 수치로 원인을 추론했다면 엉뚱한 곳을 팠다.

**F-9 — 정리 코드의 실패가 검사 결과를 덮어쓴다.**
신설 프로브가 **본 검사 23건 전건 초록인데 exit=1**로 끝났다. `finally`의 `s.from(...).delete().eq(...).catch(...)` — PostgREST 빌더는 thenable이지만 **`.catch()`가 없어** TypeError. 종료코드만 보는 게이트에서는 '검사 실패'와 구별되지 않는다.

**F-10 — 검증 중 내 검사기가 두 번 오탐했다.**
① 서빙 CSS 확인 정규식을 `\.h-sheet-hdr\{`로 썼는데 dev CSS는 미압축이라 `.h-sheet-hdr {`처럼 공백이 있어 전부 MISSING → **원복 실패로 오인할 뻔했다**.
② `plan-tab-view.tsx`의 비주석 변경 줄을 세는 정규식이 JSX 주석의 **연속 줄**을 못 알아봐 1건으로 보고.
둘 다 코드가 아니라 검사기가 틀렸다.

**F-11 — 단언 수가 평소보다 적으면 '실패'가 아니라 '중단'을 먼저 의심할 것.**
`test-sheet-entry-page` 첫 실행이 3통과/1실패였는데 이 스위트는 완주하면 28단언이다. 실패 지점은 로그인 네비게이션이었고, 당시 타 세션 E2E와 겹쳐 여유 RAM이 1.2GB였다. 재실행 28/0.
