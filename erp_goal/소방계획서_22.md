## 3. 진단 (2026-08-14, 파일:라인 근거)

### 3-1. `/`(해당없음)·무응답이 조립 단계에서 버려진다 — 최대 결손

`report9-actions.ts:313`:

```ts
if (res !== 'O' && res !== 'X') continue
```

`report4.ts:183`이 이를 인쇄물에 명시까지 한다:

> `※ 점검결과가 양호(○) 또는 불량(×)으로 기록된 점검항목만 수록하였으며, 해당없음(／)·미점검 항목은 생략하였습니다.`

`report4.ts:179`도 두 값만 렌더한다: `${it.mark === 'O' ? '○' : '×'}`.

**구체적 피해 (이미지 실측):**

- image-61의 `1-B-031·032·033`은 **전부 `/`** → 세 줄이 사라지고 `【가스·분말·고체에어로졸 자동소화장치】` 소제목도 함께 소멸.
- image-63의 `15-A-001·002`는 **둘 다 `/`** → `15-A. 경계구역` 그룹이 통째로 소멸.
- 설비의 전 항목이 `/`면 그 설비 점검표 자체가 미생성(`report9-actions.ts:305`) → **목차에도 오르지 못한다.**

법정 서식에서 `/`는 "점검했고 해당 없음"이라는 **기록**이다. 빈칸(미점검)과 의미가 다르다.

### Q-9 배경 — Q-1이 입력 UI의 전제를 깼다

`sheet-item-editor.tsx:18-25`가 `/` 버튼을 **일부러 없앤** 근거는 이랬다:

> 고를 수 있는 값은 ○·✕ 둘뿐이다(2026-08-13 확정). 고르지 않은 항목이 곧 해당없음이다.
> 왜 안전한가: 별지 4호 부속 점검표는 ○/✕인 항목만 수록하고 `/`·무응답은 **이미 똑같이 생략**한다 — **즉 문서 출력은 달라지지 않는다.**

**Q-1이 정확히 이 전제를 뒤집었다.** 이제 넷을 구분해야 한다:

| 입력 | 인쇄 | 의미 |
|---|---|---|
| `○` | `○` | 양호 |
| `✕` | `×` | 불량 |
| `／` | `/` | **점검했고 해당 없음** (Q-1) |
| 안 고름 | **공란** | 아직 안 봄 (Q-5) |

현행 UI는 뒤의 둘을 만들 수단이 없다. Q-9는 **개별 `/` 버튼을 부활시키지 않고 그룹 일괄 버튼으로만** 해소한다(2026-08-14 사용자 선택) — 미설치는 그룹 통째로 발생하므로 항목 단위 `/`가 필요한 경우가 드물다는 판단이다. 미선택의 의미가 `/`에서 **공란(미점검)** 으로 바뀌므로 `sheet-item-editor.tsx:18-25` 주석과 `:80-82`의 회색 `／` 기본값 힌트도 함께 갱신해야 한다.

**항목 단위 무응답**: 본문이 인쇄되는 시트 안에서 일부 항목만 무응답이면 **항목은 찍되 점검결과란을 공란**으로 둔다. Q-4와 같은 원리다 — 설비 단위든 항목 단위든 **서식은 온전히 찍고 결과만 비운다.**

### Q-1·Q-4 배경 — "법정 서식 그대로"의 의미와 종전 결정 번복

#### 종전 결정 원문 (`소방계획서_15.json:363`)

> **Q-2** (ref A4-1)
> **질문**: "별지 4호에 설비별 점검표 1~32번 본체를 포함할 것인가? (현재 7쪽 스코프는 의도된 설계)"
> **선택지**: `["현행 7쪽 유지", "32종까지 PDF 확장"]`
> **결정**: "점검번호 항목별 ○/× 응답이 있는 것만 PDF 수록 — /(해당없음)·무응답 항목·설비는 미생성 **(전 항목 재현이 아닌 발췌 수록)**"

당시 질문은 "점검표를 아예 안 넣나 / 32종 다 넣나"라는 이분법이었고 사용자가 중간인 **발췌 수록**을 골랐다. **그 시점엔 실제 납품 산출물 이미지가 없었다** — 법정 서식의 실물을 모르는 상태에서 내린 합리적 절충이었다.

2026-08-14에 image-60·61·63이 실물을 보여주면서 전제가 깨졌다. **image-61의 `1-B-031·032·033`은 점검결과가 전부 `/`인데 인쇄돼 있다.** 발췌 방식이면 이 세 줄이 사라진다.

#### "법정 서식 그대로"의 4개 층위

`/` 기호 하나를 더 찍는 문제가 아니다. 네 층위에서 달라진다.

| 층위 | 발췌 수록 (종전) | 법정 서식 그대로 (확정) |
|---|---|---|
| **값** | `○`·`×` 두 값만 | `○`·`×`·`/` 세 값 + 무응답 공란 |
| **행** | 응답 없으면 **행 자체 삭제** | 항목 행은 **항상 존재**, 결과란만 비거나 채워짐 |
| **그룹** | 그룹 항목이 전부 `/`면 **소제목까지 소멸**(`【가스·분말·고체에어로졸 자동소화장치】`·`15-A. 경계구역`) | 소제목·그룹 구조가 **원본 그대로 유지** |
| **설비** | `○`/`×`가 하나도 없으면 **시트 자체 미생성** → 목차에도 못 오름 | 설치된 설비는 **본문이 존재**, 결과란만 공란 (Q-4) |

즉 발췌 방식은 "점검 결과를 요약한 표"를 만들고, 법정 서식은 "정해진 서식에 결과를 채워 넣은 문서"를 만든다. **문서의 성격 자체가 다르다.**

#### 범위의 한계 — 32종 전부가 아니다

"법정 서식 그대로"가 32종 전부 인쇄를 뜻하지는 않는다. image-59의 목차는 `1·15·21·31` 넷뿐이다. **설비 선택은 설치 기준(Q-3)으로 좁히고, 선택된 설비 안에서는 전 항목을 재현한다** — 이것이 Q-1·Q-3·Q-4를 합친 정확한 의미다.

#### 구현 시 함께 걷어낼 것

`report9-actions.ts:303-305`·`report4.ts:172-174` 주석과 `report4.ts:183` 안내 문구가 발췌 정책을 명시하고 있다. 전부 갱신·삭제해야 한다.

#### S12 상세 — 부속이 페이지 1장에 몰려 있어 R-7·S4가 성립하지 않는다 (2026-08-14 발견, json `P-18`)

법정 원문은 점검표마다 **독립 쪽번호 축**을 갖는다. 추출본 전수 실측에서 `(7쪽 중 1~7쪽)`(별지 4호 본문) 뒤로 `(3쪽 중 1쪽)`·`(4쪽 중 1쪽)`·`(3쪽 중 1쪽)`… 이 설비마다 새로 시작한다. 즉 **설비별 점검표는 각각 하나의 독립 문서**다.

그런데 우리 구현은 정반대다:

```ts
report4.ts:175-191  function sheetItemPages(sections): string[] {
                      …
                      return [`…`]        // ← 전 설비를 페이지 "1장"에 몰아넣는다
                    }
report4.ts:181      ${pageHeader(null, '(설비별 점검표)')}   // ← 쪽번호가 아니라 라벨
report4.ts:184-189  <table> … 설비명은 <tr><td colspan="3"> 회색 행, 항목은 그 아래 <tr> 나열
report4.ts:174      // 주석: "내용이 A4를 넘으면 인쇄 흐름 분할"  ← 분할을 CSS에 위임
```

**두 가지가 구조적으로 막힌다.**

| 요구 | 막히는 이유 |
|---|---|
| **R-7** 설비별 `(N쪽 중 M쪽)` | 분할이 CSS 흐름에 맡겨져 **코드가 페이지 경계를 모른다.** M도 N도 계산할 수 없다 |
| **S4** 설비마다 비고 행 + 각주 4줄 | 전 설비가 **표 하나**의 `<tr>` 나열이라 설비 경계에 꼬리를 넣을 자리가 없다 |

→ **S12: `sheetItemPages(sections)`가 `string[]`을 설비 수만큼 반환하도록 재구성한다.** 설비당 1개 이상의 page를 만들고, 각 page에 자체 `pageHeader`(설비별 쪽번호)와 꼬리(비고+각주)를 붙인다. 그래야 R-7·S4가 성립하고, Q-1·Q-4로 늘어난 분량도 페이지 단위로 통제된다.

**착수 순서에 미치는 영향**: `S1 → S2 → S12 → S4`. S4를 S12보다 먼저 하면 표 하나짜리 구조에 각주를 억지로 붙였다가 S12에서 다시 뜯게 된다.

#### S1·S3 핵심 — 시트 목록의 원천이 바뀐다

Q-4가 "본문도 인쇄"로 확정되면서 **본문 시트 목록의 원천 자체가 바뀐다.** 종전에는 응답에서 시트를 역산했다:

- `report9-actions.ts:268-271` — 응답이 있을 때만 `inspection_sheet_items`를 조회(`responses.length ? … : []`)
- `report9-actions.ts:305`·`:313` — ○/× 없는 설비는 통째로 미생성

이제는 **설치 설비(Q-3)에서 시트 집합을 먼저 정하고, 그 시트의 전 항목을 카탈로그에서 가져온 뒤, 응답을 왼쪽 조인**하는 방향으로 뒤집어야 한다. 응답이 0건이어도 시트·항목이 나와야 하기 때문이다. **목차와 본문이 같은 집합을 쓰므로 둘이 어긋날 수 없다.**

부수 효과로 `responses.length === 0`일 때 `items`를 빈 배열로 두는 최적화(`:268`)를 걷어내야 한다.

| 패턴 | 건수 |
|---|---|
