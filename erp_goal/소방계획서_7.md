## 2. 현행 파이프라인 진단 — 무엇이 SDK에 묶여 있나

현행 (`scripts/make-fireplan.py`·`fireplan-worker.py`, 2026-07-15~):

```
표준양식.hwp ─(SDK)→ HWPX ─(zip+XML 치환·순수 Python)→ 병합 HWPX
                                   │
                     ─(SDK)→ 사진 삽입·HWP/ODT 저장
                                   │
                     ODT ─(로컬 LibreOffice 또는 VPS Gotenberg)→ PDF
```

| 구간 | SDK 의존 | 비고 |
|---|---|---|
| 템플릿 HWP→HWPX 변환 | **의존** (템플릿당 1회성) | 대체: 신규 구조에서는 HWPX 자체가 불필요 |
| XML 치환 병합 | 무의존 (zipfile·re) | HTML 템플릿 치환으로 개념 이전 — 병합 데이터 소스 로직은 재사용 |
| 사진 삽입 | **의존** | HTML `<img>`로 대체 |
| HWP/ODT 저장 | **의존** — PDF 변환의 입력 | HTML→PDF로 경로 자체 교체 |
| ODT→PDF (LibreOffice/Gotenberg) | 무의존 | Chromium 라우트로 교체 (LibreOffice 라우트 불필요) |
| 상주 워커 (Windows 개발 PC·작업 스케줄러) | SDK 때문에 존재 | **폐지 대상** — 개발 PC 켜져 있어야 생성되는 제약도 함께 해소 |

- 잡 큐: `fire_plan_gen_jobs`(094/095) — report_type: 소방계획서(기본)·report9·report10·report11·exterior. 클라이언트 폴링 UI(`getReport9StatusAction`·`/fire-plans/generate`·타임라인 생성 버튼)는 **그대로 재사용 가능**.
- 워커는 이미 문서별 **HTML 미리보기**를 생성해 업로드 중 (`report9_*.html`, fire_plans.html_path) — HTML 서식 재현 자산의 출발점.
- 관련 잔재: 워커 이중초기화 버그 대응(ad206d9)·작업 스케줄러 'SJFire FirePlan Worker' — 전환 완료 시 전부 소멸.

### 4-A-2. 별지 4호 작성 화면 = **설비 대장** — 소방계획서 1.4와 화면 통합 (2026-08-03 사용자 지적 반영)

> 중복 해소 2건: ⓐ 점검업무 "점검표 입력"이 **별지 4호 점검항목부의 유일한 입력** — 별지 4호에서 점검결과 재입력 없음(문서 생성 시 점검 건 응답 자동 반영). ⓑ 소방계획서 1.4 소방시설과 별지 4호 세부현황은 **같은 화면 하나(설비 대장)** — 설비 입력 화면 3곳 분산 위험 제거.

- **설비 대장 = 기존 1.4 화면(PlanForm14 — 유무 √·비고·층별 수량, facilities 저장) 확장**: 각 설비 행에 [제원 펼침] 추가 — 펼치면 별지 4호 3~7쪽 세부현황(`customer_facility_specs`) 입력. 설치(√) 설비만 펼침 가능(입력량 최소화).

### 4-A-2c. 혼동 방지 규약 — 자동/입력 구분 (2026-08-03 사용자 질문 반영)

**"데이터는 입력하고, 문서는 생성한다"** — 사용자가 "별지 4호를 입력한다"고 오해하지 않도록:

1. **이름 규약**: 입력 화면 이름은 데이터 이름(**설비 대장**) — "별지 4호"는 문서(출력물) 이름으로만. 별지 서식 그룹의 별지 4호 카드는 [미리보기]·[PDF 생성] + **"입력: 설비 대장 →"** 링크만 노출.
2. **[자동]/[입력] 배지** — 모든 별지 카드·작성 패널 공통:
   - `[자동]`(회색): 읽기 전용 + "원본: ○○" 표기 + 원본 화면 바로가기 — 여기서 못 고치고, 어디서 고치는지 즉시 안내
   - `[입력]`(보라): 직접 입력 항목만
   - 별지 4호 카드 구성 안내: `[자동] 1·2쪽 대상물·점검인력 ← 고객정보·점검 건` / `[자동] 점검결과 ○×/ ← 점검표 입력` / `[입력] 3~7쪽 세부현황 → 설비 대장`
   - 9·10·11호 작성 패널의 1단(자동 채움 검토) = [자동] 영역, 2단(③ 고유 값) = [입력] 영역 — 동일 규약
3. **미리보기 = 최종 확인**: [자동] 값은 채워진 채, 미입력 [입력] 항목만 노란 하이라이트 — 문서 모양 그대로 빈 곳 확인.

- 항목 클릭 → 해당 입력 지점 딥링크(섹션 스크롤·포커스). 저장 후 **[다음 빈칸]** 연속 이동 — 일괄 보완 모드.
- 우선순위 정렬: 제출 기한 임박(9호 D-day) 관련 빈칸 → 점검 예정 고객 → 나머지.

## 4-E. 점검 상세 여정 스텝퍼 — 업무 체크리스트·단계별 보고서·타임라인 통합 (2026-08-03 사용자 요청)

> 문제: 같은 단계 정보가 3개 섹션(6단계 업무 체크리스트·단계별 보고서 카드·문서 타임라인 ①~⑥)에 분산 —
> 처음 사용자는 다음에 무엇을 눌러야 하는지 알기 어려움.
> 확정 원칙: **"화면 순서 = 업무 순서, 지금 할 일만 열려 있다"** — 데이터 변경 없이 화면 재배치.

- **통합 세로 스텝퍼**: 3개 섹션을 ①~⑥ 스텝퍼 하나로. 각 단계 행 = 상태 아이콘 + 마감일 D-day + 그 단계의 문서·입력·행동.
- **자동 펼침**: 완료 단계는 한 줄 접힘(클릭 시 이력), **첫 미완료 단계만 자동 펼침**. 상단 "▶ 다음 할 일: ④ 별지 9호 제출 (D-3)" 배너가 동일 지점 지시.
- **단계 안에 행동 배치**: ① 점검표 진행률+바로가기 / ② 배치확인서 드롭존 / ③ 관계인 발송 / ④ 9호 작성 패널·제출일 기록 / ⑤ 불량 조치 현황+10호 / ⑥ 11호 생성·제출 패키지 — 별도 카드 탐색 제거. [자동]/[입력] 배지(§4-A-2c)·작성 패널(§4-A-2b)이 단계 안에서 열림.
- 각 단계 펼침부에 "이 단계의 할 일" 번호 목록 + 주 행동 버튼 — 처음 사용자도 클릭 대상이 명확.
- 점검표 입력(대형)은 본체 섹션 유지, ①에서 진행률과 바로가기 — 모바일 현장 동선 불변. 정기·레거시 건은 ①뿐이라 자동 단순화(분기 불필요).
- 데이터 무변경 — inspection_steps·문서 상태는 이미 단계 키로 연결. 순수 화면 재구성.

### 4-E-1. 단계별 업무 의미·문서 매핑 (2026-08-03 사용자 확인·확정 — 화면 문구의 기준)

| 단계 | 업무 의미 (처음 사용자에게 보여줄 설명) | 근거 데이터 | 문서 |
|---|---|---|---|
| ① 점검표 작성 | 현장 점검 결과 기록 (○·×·/) — **이 입력이 별지 4호 점검항목부이자 9호 3·8쪽의 재료** | 점검표 응답 | 별지 4호·9호 (자동 반영) |

### 4-E-2. 불량 전/후 사진 등록 — 등록 시점 2곳, 확인은 ⑤ 갤러리 (2026-08-03 사용자 요청)

| 시점 | 등록하는 것 | 화면 |
|---|---|---|
| **전(前)** — 불량 발견 시 | 불량 상태 사진 (photo_url) | ① 점검표에서 ×(불량) 태깅 → 불량 등록 시 **사진 첨부 슬롯** (모바일 촬영 즉시 업로드) |
| **후(後)** — 보수 완료 시 | 조치 완료 사진 (after_photo_url) | **⑤ 단계 펼침부 불량 갤러리** — 불량별 [전 사진 ‖ 후 사진] 쌍 카드에서 후 사진 업로드·교체 |

- **⑤ 단계 = 전/후 갤러리**: 불량별 카드에 전·후 사진 나란히 + 조치 내용·완료일 — "n/전체 쌍 완료" 진행률이 ⑤ 완료 판정(불량 전건 조치)과 함께 표시. 드래그&드롭·모바일 촬영 지원(기존 R0-6 드롭존 패턴).
- 전 사진 없이 넘어온 불량은 ⑤ 갤러리에서 소급 등록 가능(전 슬롯도 열림) — 단, 원칙은 발견 즉시 촬영(① 안내 문구).
- 문서 연결: 전/후 쌍은 별지 11호 증빙 패키지(zip)에 자동 첨부(기구현 유지), 9호 8쪽 불량 세부와 동일 defects 원본.
- 데이터 무변경 — photo_url·after_photo_url 기존 컬럼 그대로, 화면 배치만 ⑤ 안으로 통합(현행 별도 사진 섹션 흡수).
