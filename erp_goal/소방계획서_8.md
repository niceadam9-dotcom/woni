## 2. 현행 진단 — 왜 바꾸나

1. **입력 동선 3곳 분산**: 소방계획서=고객 상세 소방계획서 탭, 별지=점검 상세 여정 스텝퍼 또는 보고서 센터 인라인 패널. 같은 문서를 두 곳에서 고칠 수 있어 "어디서 입력하지" 혼동.
2. **회차 혼동 실사례(별그리다)**: 작동(자체) 07-25 · 작동(정기) 08-03 두 이벤트가 같은 "작동 1차" 표기 → 사용자가 월간 이벤트를 열고 "타임라인이 없다"고 혼동. (성격 배지 `작동(자체)/작동(정기)`는 2026-08-04 커밋 5588727로 선행 반영됨.)
3. **회차 관리가 어려워 보임**: 실제로는 자체점검 회차가 연 1~2개뿐인데, 계획(inspection_plan_items) vs 시작(inspections) 이중 구조와 정기(월간) 혼입 때문에 복잡해 보임.
4. **보고서 센터의 애매한 위치**: 고객별 문서 현황·별지 생성이 트리와 중복되는 별도 화면. 입력 지점이 둘로 늘어 유지·혼동 비용.

## 3. 자체점검 회차 단순화 — 연 1~2개 고정·자동

| 유형 | 자체점검 회차 | 별지 대상 |
|---|---|---|
| 작동 | 연 1회 (1차, 사용승인월) | 4/9/10/11호 |
| 종합 | 연 2회 (1차 사용승인월 · 2차 +6개월) | 4/9/10/11호 |
| 일반관리(종합/작동) | 위와 동일 (sub_type 기준) | 동일 |
| 정기(월간) | **별지 대상 아님** — 트리 회차에서 제외 | 외관점검표만(별도) |

- 회차 생성은 기존 연간 자동 생성(inspection-plan-generator.ts, 연 크론) 그대로 — **본 설계에서 회차 생성 로직 변경 없음**.
- 일반관리 동일성 검증됨: plan_type=`special_종합`/`special_작동` 동일 부여(:103), 정기 미생성(`if(!isGeneral)` :119)이라 오히려 더 단순.
- 별지 회차 트리엔 자체점검만 표시 → 정기(월간) 이벤트가 안 보여 별그리다류 혼동 원천 제거.

### 4-1. 진입: 트리 3그룹 재편 (D-10·D-12 확정)
최상위를 **역할별 3그룹**으로, 별지도 **1장 서식(1.1~1.12)과 동일한 목차 노드 문법** — 완성도 표기(✓/✎n곳/⚠)까지 같은 규칙. 별지 순서 = **점검 여정 순서**(여정 스텝퍼와 상호 설명):
```

├ 📘 소방계획서 본문                6/13
│   1장 계획 (1.1~1.12 — 1.4 설비 대장 = 별지4·9호 제원 원본 [자동])
│   2장 자위소방대 / 3장 피난계획
│   [본문 미리보기][PDF][인쇄]
├ 📑 별지 서식 (회차 자동)          ← ?form=annex
│   ⬤ 2026 작동(자체) 1차 · 진행중     ← 최신 회차 자동 펼침
│      📝 점검표 입력      [입력]  ○× 170/690 · 불량 2
│      ④ 별지 4호 점검표   [자동]  ✓
│      　 배치확인서       [외부]  ⚠
│      ⑨ 별지 9호 실시결과 [작성]  ✎3곳
│      ⑩ 별지 10호 이행계획 (불량 시만 · 기한 D-day)
│      ⑪ 별지 11호 이행완료 (불량 시만 · 기한 D-day)
│   ○ 2025 작동(자체) 1차 · 완료 ▸     ← 과거 접힘 · 펼침 시 조회 전용 톤([작성]→[열람])
└ 🗂 보관함·개정이력                ← 맨 아래
```
클릭 3계층: **별지 서식 헤더**=회차 전체 뷰(+[전체 미리보기]) / **회차 노드**=그 회차 문서 행 / **문서 노드**=즉시 미리보기(prefetch)+[작성][PDF][인쇄]. 딥링크 `?form=annex&insp={id}&doc=report9`. 종합 고객은 회차 2개(1차·2차) 동일 구조.

### 4-1b. 점검표 위치 + 배지 규약 (D-11, 2026-08-04 확정)
**「점검표 입력」= 회차 노드 첫 행** — 여정 순서(점검표→4호→배치확인서→9호→10·11호) 그대로, 원천[입력]→생성물[자동] 관계가 배치로 읽힘:
```
⬤ 2026 작동(자체) 1차 · 진행중
   📝 점검표 입력      [입력]  ○× 170/690 · 불량 2   ← 클릭=점검 상세 ① 점검표 딥링크
   ④ 별지 4호 점검표   [자동]  ✓    [미리보기][PDF][인쇄]
   　 배치확인서       [외부]  ⚠    [협회↗][업로드]
   ⑨ 별지 9호 실시결과 [작성]  ✎n곳 [작성][미리보기][PDF][인쇄]
   ⑩⑪ 이행계획·완료 (불량 시만)
```
- 점검표는 690항목 현장 입력이라 트리 임베드 대신 **진행률 표시(○× n/총 · 불량 n) + 점검 상세 딥링크**. 문서 작성·미리보기·인쇄는 트리 안에서 완결.

### 4-6. 입력↔문서 양방향 인지 (D-13) — "이 입력이 어느 문서에 쓰이나"
**구분 원칙(D-18, 2026-08-04)**: 입력 구분은 **문서별이 아닌 원천별** — 상시 입력(📘 본문 1.1~3장·1.4 설비 대장) / 회차 입력(📝 점검표·⑨ ③ 고유값·배치확인서 업로드) / 자동(④ 전체·⑨ 대부분·⑩⑪). 문서별 입력 화면을 만들면 제원이 3중 입력되므로 금지. 별지 서식 그룹 머리에 한 줄 고정 안내: `"별지는 입력한 데이터로 자동 생성됩니다. 입력: 점검표·설비 대장(1.4)·9호 ③"`.

**① 사용처 칩 (전 입력 화면 공통 규약)** — 아이콘 규약 고정: 📘계획서 · ④ · ⑨ · ⑩ · ⑪ · 외관:
```
┌ 1.4 소방시설 (설비 대장) ─────────────────────────────┐
│ 사용처: [④ 별지4호 3~7쪽] [⑨ 별지9호 4~7쪽] [📘 계획서 1.4] │ ← 클릭=해당 문서 미리보기
│ ▾ 3-1 소화기구        사용처: ④3쪽 · ⑨4쪽              │ ← 블록 단위 병기
└────────────────────────────────────────────────────────┘
```
- 칩 클릭 = 그 문서 미리보기가 **지금 입력 중인 블록 위치로 스크롤**되어 열림.
- 대상: 설비 대장(섹션 단위)·점검표 입력·9호 작성 ③·배치확인서.

**② 문서 쪽 "필요한 입력" 체크리스트 (역방향)**:

### 4-7. 별지 9호 세부현황(4~7쪽) 위치·입력 동선 (D-14·D-17)
