# 소방계획서_27 — 엑셀 산출물(손으로 고쳐 쓰는 통합 워크북)

작성: 2026-08-21. 요구: 소방계획서·별지 4호·9호·10호·11호·위임장·공문을 **엑셀 문서로** 만들어 달라.
참조본은 `erp/보고서 갑지.xls`와 `erp/경복빌딩  작동점검 보고서 2026.05.12 조병석.xls`.

## 왜 — PDF는 고칠 수 없다

현행은 전 문서가 `doc-templates/*.ts`(순수 함수) → HTML → Gotenberg → PDF다. 값이 비거나 현장에서
문서번호·수신처·결재란·대리인·비고를 손봐야 할 때, **담당자가 손댈 방법이 없다.**

사용자 확정 요구(2026-08-21 문답):

| 축 | 결정 |
|---|---|
| 용도 | **손으로 고쳐 쓰기** — 시스템이 채운 값을 엑셀에서 수정한 뒤 인쇄 |
| 서식 | **갑지 원본 그대로** — 값만 주입(병합 1,586·인쇄 여백 보존) |
| 파일 | **한 워크북 통합** — 경복빌딩 실물처럼 문서가 시트로 묶인 파일 하나 |
| PDF | **병행** — 현행 번들 유지, [엑셀로 받기]를 더한다 |

⚠ **2026-08-13의 엑셀 생성 폐지(소방계획서_21 R5-6 / _7 D-9)를 되돌리는 것이 아니다.**
그때 없앤 것은 37시트 **점검표**(operational_v2026.xlsx) 생성기이고, 이번 것은 **결과보고서 묶음**이다.
설비별 점검표 시트 결합은 이 차수의 범위 밖으로 둔다(§Phase 5).

## 실측 ① — SheetJS로는 만들 수 없다 (접근법을 가른 측정)

갑지를 SheetJS 0.18.5로 읽고(`cellStyles:true`) 다시 쓴 뒤 재독:

| 축 | 원본 | 왕복 후 |
|---|---|---|
| 총 셀 | 11,138 | **1,977** |
| 빈 서식 셀(`t:'z'`) | 9,162 | **0** |
| 병합셀 | 1,586 | 1,586 (보존) |
| `!cols`/`!rows`/`!margins` | 있음 | 보존 |
| 셀 스타일에 실린 키 | `patternType`·`fgColor`·`bgColor` (312셀) | `patternType` |

`border`·`font`·`alignment`는 **읽기 단계에서 이미 0건**이다(11,138셀 전수). 즉 쓰기 지원 여부와
무관하게 잃는다. 그리고 법정 서식의 격자는 대부분 **값 없는 칸**이라, 빈 서식 셀 9,162개가 사라지면
갑지는 "병합 정보만 남은 백지"가 된다.

> `scripts/_probe-xlsx-rebuild.mjs`가 검증하던 것은 "열리는가"였지 "서식이 사는가"가 아니었다.
> `scripts/dist_operational_v2026.xlsx`(`_assemble-report-template.mjs:55` 산출물)는 이 손실을 이미
> 겪은 파일이라 템플릿 자산으로 쓸 수 없다.

## 결정

- **D-1 도구: JSZip 바이트 패치.** exceljs가 아니다. ①`jszip@3.10.1`은 이미 설치돼 있고
  (`package.json:27`, `timeline-actions.ts:4` 사용 중) exceljs는 미설치 ②exceljs는 워크북을 **재방출**
  하므로 모델링 안 된 요소가 조용히 탈락하지만, JSZip 패치는 **손대지 않은 바이트가 그대로** 남아
  병합·인쇄여백·인쇄영역·정의된이름·그림·조건부서식 무손상이 **구성적으로** 보장된다
  ③`lib/doc-overrides.ts:11`("파서를 쓰지 않는다 — 의존성 0")과 같은 철학이다.
- **D-2 템플릿 자산화는 LibreOffice로 1회.** SheetJS로 .xls→.xlsx 변환하면 실측①이 그대로 재현된다
  (`scripts/_upload-report-template.mjs:7`이 정확히 그 실수를 했다). 로컬 soffice로 변환해 커밋한다.
- **D-3 주입은 `개요` 허브에만.** 스포크는 수식이 채운다. 어긋날 지점을 117 → 40으로 줄인다.
- **D-4 재계산에 기대지 않는다(기안 결정 폐기).** 처음엔 `<calcPr fullCalcOnLoad="1">`만 켜면 스포크가
  따라온다고 봤으나 **실측으로 틀렸다** — LibreOffice는 이 플래그를 무시하고 옛 `<v>`를 그대로 보여준다
  (패치 후에도 `공문!B8`·`보고서!C4` = "정내과의원"). 플래그 자체는 남긴다: 사용자가 Excel에서 허브를
  고치는 순간부터는 수식이 살아 움직이는 편이 낫다.
- **D-9 캐시값 동시 주입 + 이행 폐포.** 허브를 바꿀 때 그 값을 참조하는 셀의 **캐시값 `<v>`도 함께
  갱신**한다(`<f>`는 보존). 전파는 반드시 **이행 폐포**여야 한다 — 간선이 두 종류이고
  (시트 넘김 `'개요'!B14`, 같은 시트 안 `A3`) 스포크가 스포크를 참조하는 사슬이 있다
  (`완료보고서!B5 = '계획서'!B5`, `계약서!D24 = A3`).
  **실측: 1단계만 하면 옛 값 4회 잔존 → 폐포만 2회 → 시트 내 참조까지 넣어 0회.**
- **D-10 모르면 비운다.** 기계 전파가 불가능한 복합 수식 셀이 스크럽 대상 값을 물고 있으면 `<v>`를
  **비운다**. 빈칸이 남는 것이 남의 상호·이름이 남는 것보다 낫다.
- **D-5 저장하지 않는다.** `bundle/route.ts:9`의 선례: "저장하면 그 자체가 새 가비지". 엑셀은 사용자가
  받아 고치는 순간 서버 사본이 낡는다. 즉석 생성 라우트로 응답만 한다.
- **D-6 `fire_plan_gen_jobs`에 기록하지 않는다.** 그 테이블은 `{type}_{stamp}.pdf` 파일 규약과 짝이라
  (`bundle-actions.ts:74`·`bundle/route.ts:57`), 파일 없는 엑셀을 넣으면 문서 현황·번들 체크리스트가
  "생성됐는데 파일이 없다"로 어긋난다.
- **D-7 조회 코드는 새로 쓰지 않는다.** 기존 `assemble*`의 반환을 그대로 앵커 값으로 변환한다.
  그러면 `annex_inputs` 수동 오버레이(`report9-actions.ts:180-195`)가 공짜로 따라오고,
  **PDF와 엑셀이 같은 값을 쓴다는 것이 구조적으로 보장**된다.
- **D-8 SheetJS는 읽기·검증 전용.** 앞으로 이 저장소에서 `XLSX.write`로 산출물을 만들면 실측①이
  조용히 재발한다. `lib/xlsx-inject.ts` 머리에 못을 박는다.

## 앵커 — 좌표를 쓰되 좌표만 믿지 않는다

`lib/doc-overrides.ts`가 같은 문제를 이미 풀었다: `:315` 키+해시+라벨 3중 일치 → `:321` 라벨로 재탐색해
유일하면 자가치유 → `:329` 라벨만 같고 내용이 바뀌었으면 적용하되 `blocked`로 생성 차단.
"법정 문서에선 조용히 붙이는 것도 조용히 버리는 것도 안 된다"(`doc-overrides.ts:16-18`).

갑지의 `개요`는 **A열이 라벨, B열이 값**(`A14="상호 "`/`B14`)이라 라벨 검증이 그냥 옆 셀이다 — HTML
쪽보다 앵커가 강하다.

```
{ field:'customerName', sheet:'개요',   cell:'B14', labelCell:'A14', label:'상호', kind:'value' }
{ field:'agentName',    sheet:'위임장', cell:'N6',  labelCell:'K6',  label:'성명', kind:'formula-replace' }
```

**세 겹 방어**
1. **로드 시 전수 검증** — `labelCell` 실값 ≠ `label`이면 **생성 실패**(조용한 오적용 금지)
2. **자가치유** — 같은 시트에서 라벨 재탐색, 유일하면 이동 + 경고(행이 밀려도 살아남는다)
3. **완전 덮어쓰기 불변식** — `개요`의 모든 입력 셀은 (주입값 | 명시적 공란) 둘 중 하나.
   앵커에 없는 입력 셀이 있으면 테스트 실패. **남의 개인정보 인쇄를 막는 유일한 장치다.**

`lib/xlsx-template-manifest.json`(sha256 + 시트 26 + 병합 1,586)을 함께 둔다 — 갑지가 갱신되면
테스트가 먼저 붉어지고, 그때 앵커를 재승인한다.
