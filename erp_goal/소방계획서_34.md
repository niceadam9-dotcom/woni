## 0. 왜 34가 필요한가

지금 별지 서식(별지 4·9·10·11호 + 표지·공문·위임장)은 고객 상세의 **소방계획서 탭 안**, 좌측 목차 트리 맨 아래 노드다.

```
고객 상세
 └ [소방계획서] 탭
     ├ 📘 소방계획서 본문   1.1 … 1.12 / 2장 / 3장 / 보고서 커버
     ├ 🗂 보관·이력        보관함·개정이력
     └ 📑 별지 서식        회차별 작성·조회      ← 여기
```

### 실측 근거 (직접 Read로 확인, 2026-08-29)

| 위치 | 실제 코드 | 의미 |
|---|---|---|
| `erp/src/components/customers/plan-tab-view.tsx:403-406` | `<p>📑 별지 서식</p>` + `navBtn('annex', '회차별 작성·조회', true)` | 별지는 트리의 한 노드 |
| 같은 파일 `:462` | `{sel === 'annex' && (annex ?? …)}` | 노드를 눌러야 마운트되는 **지연 로드** |

### 문제

**성격이 다른 두 업무가 한 탭에 겹쳐 있다.**

| | 소방계획서 본문 | 별지 서식 |
|---|---|---|
| 주기 | **연 1회** 작성·개정 | **회차마다** 반복 |
| 산출물 | 계획서 1건 | 회차별 4~7종 PDF |
| 주 동선 | 서식 트리 탐색(1.1 → 1.2 → …) | 회차 카드 펼침·생성·인쇄 |
| 데이터 원천 | 고객·건물·대장 | 점검 결과·점검표 |

가장 자주 쓰는 화면이 **2단계(탭 → 트리 노드) 안쪽**에 묻혀 있다. 실제로 달력·최근고객 칩·헤더 버튼([소방계획서_30](소방계획서_30.md) 동선 3직행), 점검 상세, 작업대, 제출현황판, 대장, 커맨드 팔레트가 전부 `?tab=plan&form=annex`라는 **2단 딥링크**로 이 노드를 직접 겨눈다 — 13곳이 같은 우회로를 각자 적고 있다는 사실 자체가, 별지가 이미 독립 목적지라는 증거다.

→ **별지 서식을 `[소방계획서]` 탭 바로 오른쪽의 최상위 탭 `[별지서식]`으로 승격한다.**

```
[기본정보] [건물·시설] [관계인] [소방계획서] [별지서식] [청구·수금] [이력]
                                     ↑ index 3    ↑ index 4 (신설)
```

## 2. 설계 요지

### 2.1 탭 셸은 패널을 **전부 렌더**한다 — 이 승격의 최대 리스크

`customer-tabs.tsx:142-146`:

```tsx
{tabs.map(t => (
  <div key={t.key} role="tabpanel" hidden={active !== t.key} className="space-y-6 pt-5">
    {panels[t.key]}
  </div>
))}
```

`hidden`으로 감출 뿐 **마운트는 전부 한다**. 이건 버그가 아니라 계약이다 — `:7-8`이 "패널은 전부 서버 렌더 후 show/hide — 탭 전환에도 각 폼의 입력 상태가 유지된다"고 명시한다.

그런데 `PlanAnnexSection`은 마운트 즉시 회차 조회 서버액션을 왕복한다(`plan-annex-section.tsx:121` → `reload(true)` → `getCustomerRoundsAction`). 지금은 트리 노드를 눌러야만 도는 지연 로드다(`plan-tab-view.tsx:462`).

**그대로 최상위 패널로 올리면 기본정보 탭만 열어도 별지 회차 조회가 매번 돈다.** 고객 상세 전체의 TTI 회귀이고, 증상이 "좀 느려졌다"뿐이라 아무도 못 알아챈다.

→ `CustomerTabs`에 **`lazyKeys`** 를 신설한다.

```ts
lazyKeys?: string[]   // 처음 활성화될 때까지 패널을 렌더하지 않는다 (무거운 클라이언트 패널)

const visited = useRef<Set<string>>(new Set([validInitial]))
if (!visited.current.has(active)) visited.current.add(active)
…
const skip = lazyKeys?.includes(t.key) && !visited.current.has(t.key)
<div … hidden={active !== t.key}>{skip ? null : panels[t.key]}</div>
```

**한 번 방문하면 계속 마운트를 유지**해야 한다 — 안 그러면 `:7-8`의 입력 상태 유지 계약이 깨진다. `active` 변경이 이미 렌더를 일으키므로 `visited`는 `useRef`로 충분하다.

### 2.2 카드 껍데기는 `PlanTabView` 것이다 — 같이 안 옮기면 맨몸으로 뜬다

지금 별지는 `plan-tab-view.tsx:290`의 카드 안에서 그려진다.

```tsx
<div className="bg-surface rounded-xl border border-line shadow-[rgba(18,43,165,0.08)_0px_1px_1px_-0.5px,…] p-5">
```

`PlanAnnexSection`(`:321` `<div className="space-y-3">`)은 자기 껍데기가 없다. 탭으로 꺼내면서 이 래퍼를 복제하지 않으면 **회차 카드가 페이지 배경 위에 테두리 없이** 뜬다.

### 2.3 `annex` prop은 남기지 말고 지운다

`PlanTabView`의 `annex?: ReactNode`를 남겨 두면 ①누군가 트리 노드를 되살릴 여지가 남고 ②두 곳에서 마운트되면 회차 조회 왕복이 이중으로 뜬다. 지우면 타입체커가 유일한 호출부(`page.tsx:761`)를 정확히 지목한다.

### 2.4 같은 경로 `?tab=` 이동은 서버를 안 깨운다

**이 문서에서 가장 중요한 함정.** 같은 pathname으로 `?tab=`/`?form=`만 바꾸는 `next/link` `<Link>`나 `router.push`는 URL만 바뀌고 **서버가 재렌더되지 않는다**. `page.tsx:934-938`이 이미 실측 주석으로 못박고 있다:

> ⚠ Link가 아니라 `<a>`다(전체 이동). 같은 경로에서 `?tab=`만 바꾸는 soft navigation은 URL만 바뀌고 **서버가 재렌더되지 않아** initialTab·initialForm이 옛 값 그대로다 — 2026-08-28 실측: tab=buildings에서 눌러도 활성 탭이 건물·시설로 남았다.

`customer-tabs.tsx:44-48`(`prevInitialRef`)과 `plan-tab-view.tsx:123-130`(`prevFormRef`)의 프롭 동기화는 **둘 다 그 재렌더를 전제**한다.

지금까지는 별지가 소방계획서 탭 **안**에 있어서, 별지↔1.4 왕복이 `prevFormRef` 하나만 걸리면 됐다. 탭이 갈라지면 `prevInitialRef` + `prevFormRef` **둘 다** 걸려야 한다 — 실패 시 사용자는 화면에 그대로 남고 아무 일도 안 일어난 것처럼 보인다.

→ 같은 경로 이동은 **전체 이동(`<a>` / `window.location.assign`)** 또는 **탭 셸 컨텍스트 `goTab()`** 으로만 한다.
