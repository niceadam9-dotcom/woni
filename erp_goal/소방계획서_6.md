## 5. 미결 4건 — 전부 확정 (2026-07-28 사용자 결정: 권장안 확정 + ③ 수정)

**최종 결정 요약**: ① 일괄 '작동' 백필 확정 ② 2026 소급 생성 확정 ③ (수정) **미시작·진행 중 event는 삭제하고 새 체계로 대체** — 완료 기록·외관점검표만 읽기 전용 보존 ④ 요금 모델 현행 유지, 연 2회 청구 횟수는 착수 후 결정. 소방계획서·필수필드는 **즉시 전면 적용**(소방안전관리와 동일 원칙 — ⚠ 미보유는 '할 일'로 정상 노출).

아래는 결정 근거 기록:

1. **기존 일반관리 고객의 종합/작동 지정** — 권장: **일괄 '작동' 백필 + 예외만 수정**.
   근거: 종합점검 대상은 법령상 특정 요건(스프링클러 등) 건물이라 일반관리(소규모)에선 소수 — 다수를 기본값으로, 소수만 손(입력 3원칙). 안전장치: ⓐ 백필 후 고객 목록 일반관리 필터로 종합 대상만 수정(유형 변경 시 계획 재생성 기존 로직) ⓑ 생성 계획은 planned라 확정 전 실동작 없음. 착수 시 조사: 일반관리 고객 수·종합 요건 해당 고객 파악.
2. **소급 생성 범위** — 권장: **올해(2026) 소급 생성**, 기존 "지난 달 생성 생략" 규칙 재사용.
   근거: 2027부터면 일반 고객 올해 자체점검 부재 = 개편 취지 모순. 소급분 전부 planned → 이미 event 방문 마친 고객은 확정 안 하면 중복 방문 없음. 2026 1회성 백필 스크립트, 2027부터는 12/1 크론 자동.
   ⚠ **유니크 충돌 명시 처리 (2026-07-28 검증 발견 → §5-3 결정으로 단순화)**: `inspection_plan_items UNIQUE(plan_id, customer_id, sequence_num)`(`005:50`) — 기존 event(기준월·sequence 1)와 소급 1차 특별(같은 월·sequence 1)이 충돌해 1차가 조용히 생성 생략된다(23505 무시 멱등 `generator:163`). §5-3 확정(미시작·진행 중 event 삭제)에 따라 **소급 순서 = event 삭제 → 소급 생성**이므로 충돌은 **완료 event만** 남음 → 완료 건은 "올해 방문 이행 간주·1차 생성 생략"을 **로그로 기록**(조용한 스킵 금지).
3. **기존 event 건 처리** — **확정(2026-07-28 사용자 결정, 권장안 수정)**: **미시작·진행 중 event는 삭제하고 새 체계(special_*)로 대체. 완료 event·외관점검표만 읽기 전용 보존**.
