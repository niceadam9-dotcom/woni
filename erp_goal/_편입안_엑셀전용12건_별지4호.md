### ⚠ 주의 — 글머리는 설비마다 다르다

`감시제어반과 수신기 간 상호 연동 여부`는 **설비 3에서 `●`(종합 전용), 설비 4에서 `○`(작동 공통)** 이다. 문장만 보고 전역 매핑을 만들면 틀린다. 위 표는 각 설비 구간의 원문 표기를 그대로 옮겼다.

같은 방식으로 현행 DB를 검사하니 **기존 항목 24건이 원문 표기와 어긋나 있다**(일치 708 · 불일치 24 · 원문 미발견 98). 이번 편입 범위 밖이라 손대지 않았지만, 별도 과제로 남길 값어치가 있다 — 종합점검 전용 항목이 작동점검에 뜨거나 그 반대가 되는 문제다.

## 함께 고쳐야 할 것 — 펌프성능시험 대상 설비 (V21-1)

편입 대상인 **설비 13이 펌프성능시험 표를 가진 설비**라, 두 문제가 같은 면에서 맞물린다.

원문을 다시 세어 보니 `※ 펌프성능시험` 표가 붙는 설비는 **9개**다:

> 2(옥내소화전) · 3(스프링클러) · 4(간이스프링클러) · **5(화재조기진압용 스프링클러)** · 6(물분무) · 7(미분무) · 8(포소화) · **13(옥외소화전)** · 32(다중이용업소)

현재 구현(`lib/pump-test.ts`의 `PUMP_TEST_SHEETS`, 마이그레이션 131의 `CHECK`)은 **6개(2·3·4·6·7·8)** 뿐이다 — **5와 13이 빠졌다.**

- **13(옥외소화전)**: DB에 `STD-13`이 실재하므로 지금 바로 영향이 있다. 옥외소화전 펌프 실측치를 입력할 자리가 없다.
- **5(화재조기진압)**: DB에 `STD-05` 시트 자체가 없어 당장은 화면에 나타나지 않지만, CHECK에 넣어 두지 않으면 나중에 시트를 추가하는 순간 저장이 막힌다.
- **32(다중이용업소)**: 별지 4호가 이 축을 `muResults`(MU-001~016)라는 **다른 모델**로 담는다. 항목 코드 체계가 달라 `inspection_pump_tests`의 `sheet_no`에 넣으면 두 축이 섞인다. **제외하되 사유를 코드 주석에 남긴다.**

→ `PUMP_TEST_SHEETS = [2, 3, 4, 5, 6, 7, 8, 13]`, 131의 `CHECK`도 같은 집합으로.
**코드만 고치면 저장이 CHECK 위반으로 조용히 실패한다** — 마이그레이션과 코드를 함께 넣어야 한다.

## 실행 상태 — 마이그레이션 132는 이미 작성돼 있다

이 편입안을 쓰는 사이 다른 세션이 같은 결론에 도달해 **`132_annex4_missing_items.sql`** 을 만들어 뒀다.
내용을 대조하니 **12건·코드·order_num·comprehensive_only가 모두 일치**하고, 펌프 대상 설비 확장(②)까지 함께 담고 있어 더 완전하다. 중복이므로 별도 마이그레이션은 만들지 않는다.

- ① 12개 항목 편입 — `sheet_id` UUID 직접 지정, `NOT EXISTS`로 재실행 안전
- ② `inspection_pump_tests.sheet_no` CHECK를 `(2,3,4,5,6,7,8,13)`으로 확장
- `lib/pump-test.ts`의 `PUMP_TEST_SHEETS`도 이미 8개로 수정돼 있다

### 🔴 지금 코드와 DB가 어긋나 있다 (적용 전이라 발생 중)

`PUMP_TEST_SHEETS`는 8개인데 **DB의 CHECK는 아직 6개**다. 실측으로 확인했다:

```
sheet_no=13 -> CHECK 위반
sheet_no=5  -> CHECK 위반
```

즉 지금 화면에서 **옥외소화전 탭이 보이지만 저장하면 실패한다.** 132를 적용하면 해소된다 — 적용 전까지는 이 상태다.

2. 스테이징에서 같은 프로브를 돌린다 — 로컬과 **완전히 같은 명령**이고 BASE만 바꾼다:

   npx tsx scripts/_probe-r57-visual.mts     # 두 PDF 생성 (운영과 같은 Gotenberg)

3. 나온 `annex4.pdf` · `excel.pdf`를 나란히 열어 **눈으로** 본다. 볼 것:
   - 제어반 면(3면/4면)의 칸 배치가 서식과 맞는가
   - 펌프성능시험 표의 4행 × 3열 + 적정 여부 칸이 한 쪽에 들어가는가
   - 부속 설비별 점검표의 쪽 나눔이 항목을 잘라 먹지 않는가

⚠ 프로브는 시드를 **일부러 남긴다** — PDF를 사람이 열어 봐야 끝나는 작업이라 자동 정리하면 재현이 안 된다. 정리는 5번에서 명시적으로 한다.

2. 점검 상세 ①에서 12개 항목이 뜨는지, **옥외소화전에 펌프 표가 붙고 저장되는지** 확인
3. 별지 4호 렌더에 12개 항목이 실리는지 확인 (`getAnnexPreviewHtmlAction('report4')`)
4. **그 다음에야** R5-6(엑셀 생성 폐지) 착수

**순서를 뒤집지 않는다.** 3까지 확인되기 전에 엑셀을 지우면 12건이 유실된다.

### R5-6 착수 시 제거 대상 (참고)

`report-generate-actions.ts`(generate·printOperationalReportAction) · `lib/report-generator.ts` · `report-generate-client.tsx` · `[id]/page.tsx`의 [기타 도구] 블록 · 템플릿 `reports/templates/operational_v2026.xlsx`.
`_probe-c1-blocks.mjs`가 엑셀 버튼의 존치를 단언하고 있어 함께 갱신해야 한다.
