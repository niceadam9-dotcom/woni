## 0. 왜 35가 필요한가 — **원인이 하나가 아니다**

사용자 요구는 한 문장이다.

> "소방계획서 1.4 소방시설 세부제원, 시니어분들이 잘 보이지 않아 글씨 폰트를 확대하고 선명하게."

그런데 **"확대"와 "선명"은 서로 다른 두 원인**에서 온다. 이 문서의 핵심 판정은 그 분리다.

### 축 1 — 선명함: **한글 웹폰트가 아예 없다**

`erp/src/app/layout.tsx:5-15`가 next/font로 두 폰트를 로드한다.

```ts
const plusJakartaSans = Plus_Jakarta_Sans({ subsets: ["latin"], weight: [...] });   // :5-9
const inter           = Inter({           subsets: ["latin"], weight: [...] });   // :11-15
```

**둘 다 `subsets: ["latin"]`이다. 두 폰트에 한글 글리프가 없다.** 그러므로 `globals.css:302`의 스택

```css
font-family: var(--font-plus-jakarta-sans), var(--font-inter), ui-sans-serif, system-ui, sans-serif;
```

에서 **모든 한글은 앞의 둘을 건너뛰고 `system-ui`로 폴백**된다 — Windows에서 맑은 고딕(Malgun Gothic)이다. 즉 지금 ERP가 화면에 그리는 한글은 **웹폰트가 아니라 OS 폰트**다. 맑은 고딕은 작은 크기에서 획이 가늘고 힌팅이 약해 뿌옇게 보인다.

여기에 `globals.css:303`이 한 겹 더 얹는다.

```css
letter-spacing: -0.01em;   /* 라틴 디스플레이용 조임이 한글 자간까지 좁힌다 */
```

두 축으로 부재를 확정했다(단일 Grep은 근거가 못 된다 — [[feedback_grep_stale_two_axes]]):
- ① `Grep "@font-face"` 저장소 전체 = **0건**
- ② `erp/public/` 실물 = svg 5개, 폰트 **0개**

`erp/assets/fonts/NanumGothic-{Regular,Bold}.ttf`가 있으나 **웹으로 서빙되지 않는다.** 참조자는 `Dockerfile:54-55`(컨테이너 fontconfig), `scripts/assert-korean-glyphs.mjs`, `lib/static-map-compose.ts:101` — 전부 **서버 렌더 전용**이다(별지 PDF·정적 지도의 두부 방지, [[risk_tofu_detection]]).

> **이것이 "선명하지 않다"의 절반 이상이다.** 크기를 아무리 키워도 맑은 고딕은 맑은 고딕이다.

### 축 2 — 크기: **px 하드코딩이 흩어져 있다**

소방계획서 화면의 폰트 크기 클래스 실측(12개 `plan-form*.tsx` 기준):

| 클래스 | 개수 | 실 px |
|---|---:|---|
| `text-[11px]` | 122 | 11 |
| `text-xs` | 92 | 12 |
| `text-[10px]` | 43 | 10 |
| `text-sm` | 6 | 14 |
| `text-[9px]` | 2 | 9 |
| `text-base` / `text-2xl` | 1 / 1 | 16 / 24 |

1.4 두 파일만 **78곳**(`plan-form14.tsx` 33 · `plan-form14-specs.tsx` 45). 세부제원 표의 헤더는 **9px**, 입력칸은 **11px**다.

Tailwind v4 `@theme inline`을 쓰고 `tailwind.config` 파일이 없으며, **fontSize 스케일 커스터마이즈가 없다**(기본 스케일 그대로). 즉 크기를 조정할 **단일 지점이 현재 존재하지 않는다.**

**중요한 부수 사실:** `text-[11px]` 같은 임의값은 **line-height를 설정하지 않는다**(preflight `html{line-height:1.5}` 상속). 반면 `text-xs`는 `--text-xs--line-height: calc(1/0.75)`를 함께 건다(`node_modules/tailwindcss/theme.css`). **이 차이를 보존하지 않으면 "크기만 바꿨는데 줄간격이 변하는" 회귀가 난다.**

## 3. 설계 판정

### 3-1. 배율 방식 — 루트 리사이즈 ❌ / **CSS 변수** ✅

`html { font-size: 115% }` 방식은 **두 가지로 실패한다.**

1. **안 먹는다.** 259곳 중 **167곳(`text-[9/10/11px]`)이 px 리터럴**이라 루트 크기와 무관하다. `rem` 기반인 `text-xs`(92곳)만 커진다.
2. **역전이 난다.** `text-xs`만 12→13.8px로 커지면, 원래 12px였던 라벨이 11px 라벨보다 커지는 정도가 아니라 **위계가 뒤섞인다.**
3. 게다가 루트 리사이즈는 사이드바·헤더·달력까지 번져 **결정 1(소방계획서만)을 위반한다.**

→ **`--fs-scale` CSS 변수 + `calc()`.**

변수는 **`<html data-fs="lg">`에 건다.** 컨테이너 `<div>`가 아닌 이유: 1.4 세부제원 패널이 `fixed inset-0`(`plan-form14.tsx:698`)이고 미저장 확인창(`unsaved-nav.tsx:94`)도 그렇다. **fixed 요소는 조상 스코프를 벗어난 것처럼 보이는 경우가 있고, 향후 `createPortal`을 쓰면 확실히 샌다.** `<html>`에 걸어도 스코프는 안전하다 — `text-form-*` 유틸리티를 쓰는 화면 밖에서는 변수가 **소비되지 않기 때문**이다. 스코프를 위치가 아니라 **이름으로 보장**한다.

### 3-2. 치환 전략 — 컨테이너 상속 ❌ / **시맨틱 토큰 코드모드** ✅

**컨테이너에 `font-size`를 걸고 상속으로 덮는 안은 작동하지 않는다.** 259곳 전부가 자식 요소에 명시적 `font-size` 유틸리티를 갖고 있어 상속이 도달하지 않는다.

그 변종 — **명시도로 덮기**:
```css
[data-fs] .text-\[11px\] { font-size: calc(11px * var(--fs-scale)) }   /* (0,2,0) > (0,1,0) */
```
파일 수정 0이라 되돌리기가 쉽다. 하지만 **`text-[11px]`이라는 문자열이 곧 의미가 되는 암묵 결합**을 만든다:
- 앞으로 그 화면에 `text-[11.5px]`을 쓰면 **조용히 배율에서 빠진다**
- 다른 화면 코드를 복사해 오면 **의도치 않게 커진다**
- 두 경우 다 회귀가 **"화면을 봐야만 아는"** 종류로 남는다

→ **시맨틱 토큰 + 코드모드.** 그리고 결정적 이점은 되돌리기가 아니라 **증명 가능성**이다:

> ### ⭐ 치환과 확대를 분리한다 — **1단계는 항등(identity) 치환**
>
> `text-form-xs`의 초기값을 **11px 그대로** 둔 채 코드모드를 돌린다. 그러면 S2의 수용 기준이 **"픽셀이 하나도 안 변했다"**가 되고, 이건 computed font-size 다중집합·스크린샷으로 **기계가 증명**한다.
>
> 그 다음 **CSS 6줄**의 값만 올려 확대를 켠다. 회귀가 나면 `git revert`(16파일)가 아니라 **변수 한 줄 되돌리기**로 끝난다.
>
> 이건 명시도 덮기 안이 흉내낼 수 없는 성질이다 — 그 안은 치환과 확대가 **같은 한 줄**이라 분리할 수 없다.
>
> 선례: 소방계획서_29의 "라이트 모드 픽셀 불변" 규약([[project_soban29]]). 대조군을 먼저 보이는 것과 같은 축([[project_sheet_entry_concurrent]]).

### 3-4. Pretendard — 스택 **후미**에 넣는다

```css
/* src/app/pretendard.css — globals.css에서 @import */
@font-face {
  font-family: 'Pretendard Variable';
  font-weight: 45 920;
  font-display: swap;
  src: url('/fonts/pretendard/woff2/PretendardVariable.subset.0.woff2') format('woff2-variations');
  unicode-range: U+AC00-D7A3;   /* 조각별로 분할 */
}
```
```css
/* globals.css:302 · :306 */
font-family: var(--font-plus-jakarta-sans), var(--font-inter), 'Pretendard Variable', ui-sans-serif, system-ui, sans-serif;
```

**후미에 넣는 이유가 이 설계의 핵심 안전장치다.** 라틴·숫자는 PJS/Inter가 먼저 잡고 **한글만** Pretendard로 내려온다. 결과:
- `tabular-nums` **숫자 폭이 안 변한다** → §2-4의 표 폭 계산이 그대로 유지된다
- ERP **전 화면의 영문 UI가 픽셀 불변**이다
- 그러면서 사용자가 체감하는 "선명해졌다"는 **그대로 얻는다** (화면의 한글은 전부 바뀌므로)

Pretendard를 맨 앞에 두면 ERP 전 화면의 영문·숫자 폭이 동시에 바뀌어 **회귀 표면이 몇 배**가 된다 — 이번 작업 범위를 넘는다.

**next/font 2종과 공존:** next/font는 `--font-*` CSS 변수만 만들고 `layout.tsx:30`에서 `<html>` 클래스로 붙는다. 우리 `@font-face`는 **이름**(`'Pretendard Variable'`)으로 참조되므로 충돌하지 않는다.

**dynamic-subset을 고르는 이유:** 한글은 사용자 데이터(건물명·주소·비고)가 무제한이라 **UI 어휘 기반 정적 서브셋은 두부를 낸다.** 완전 음절(11,172자) 단일 파일은 ~1.1MB. dynamic-subset은 `unicode-range` 조각으로 쪼개 **실제 쓰인 조각만** 내려받는다(실무 전송 150~300KB). ⚠ §8 R-2로 실측.

**`font-display: swap`:** FOUT(맑은 고딕 → Pretendard 리플로우)가 밀집 표에서 보인다. `optional`은 느린 첫 로드에서 **영영 적용 안 될 수 있어** 사용자 요구를 배신한다. → **swap 유지 + 가장 흔한 조각 2~3개 `<link rel="preload">`.** preload 대상은 S1에서 실제 화면 텍스트로 실측해 고른다.

**letter-spacing:** `globals.css:303`의 `-0.01em`은 라틴 디스플레이용 조임이다. **body 전역을 건드리지 않는다**(ERP 전 화면 텍스트 폭이 흔들린다). 대신 `text-form-*` 유틸리티 각각에 `letter-spacing: normal`을 넣는다. 단 이것은 **항등이 아니므로 S3에 묶고 S2에는 넣지 않는다.**

**라이선스:** OFL 1.1. `public/fonts/pretendard/OFL.txt` 동봉(선례 `erp/assets/fonts/OFL.txt`) + `README.md`에 버전·출처·서브셋 생성 방법 기재.

**캐시:** `next.config.ts` `headers()`에 `{ source: '/fonts/:path*', headers: [{ key:'Cache-Control', value:'public, max-age=31536000, immutable' }] }`. `/public`은 기본 `max-age=0`이라 매 요청 재검증한다.

## 6. 검증 계획 — **항진명제 차단이 설계의 일부다**

### 수용 기준

**A. 한글 폰트**
- **A-1** `public/fonts/pretendard/` woff2 sha256이 고정 목록과 일치하고, dev 서버가 `200 + content-type: font/woff2`로 서빙한다
- **A-2** 1.4 화면의 한글이 **Pretendard로 그려진다** (판정법은 아래 검사 1)
- **A-3** `/fonts/*` 응답에 `Cache-Control: ... immutable`
- **A-4** **라틴·숫자 렌더 폭 불변** — rowtable 숫자 셀의 `Range.getClientRects()` 폭이 S0과 동일 (§3-4 후미 배치의 실증)
- **A-5** `OFL.txt`가 폰트와 같은 디렉터리에 있다

**B. 크기**
- **B-1** S2 시점에 대상 화면 computed font-size **다중집합이 S0과 완전 일치** (항등 치환 증명)
- **B-2** S3 시점에 1.4 세부제원 최소 font-size ≥ 11px, 본문 라벨 ≥ 13px
- **B-3** 16파일에 남은 `text-[Npx]`·`text-xs`·`text-sm`·`text-base` = **0건** (`text-2xl` 1건 화이트리스트)
- **B-4** 배율 md/lg/xl에서 **같은 요소**의 font-size 비 = 1 : 1.15 : 1.3 (±0.5px)

**C. 레이아웃**
- **C-1** 배율 **md·lg**에서 1.1~3장 모든 표·`overflow-x-auto` 래퍼에 대해 `scrollWidth ≤ clientWidth + 1`
- **C-2** 배율 **xl**에서는 표 가로 스크롤 허용, 단 **`document.documentElement.scrollWidth ≤ clientWidth`**(페이지 전체는 전 배율 금지)

- **D-6** **154 미적용 DB에서도** 로그인·화면 정상 (관용 조회)

### 검사 설계 — 항진 경로와 차단

#### 검사 1 — "Pretendard로 **그려졌다**" (A-2)

**나이브한 검사가 항진명제가 되는 경로 3가지:**
1. `document.fonts.check('13px Pretendard','소방')` → **폰트가 로드만 되면 true.** body 스택에 안 넣어도 통과한다.
2. `getComputedStyle(el).fontFamily.includes('Pretendard')` → **선언된 스택**을 돌려줄 뿐. 파일이 404여도 통과한다.
3. 캔버스 `measureText`를 Pretendard 하나로만 재기 → 폴백으로 그려져도 "폭이 나왔다"로 통과.

> 이건 [[risk_tofu_detection]]과 같은 함정이다 — **'로드됐다'와 '그걸로 그려졌다'는 다른 축**이고, 단일 측정은 둘을 구별하지 못한다.

**설계 — 3중 폭 대조 + 실물 요소:**
```
targetW  = 실제 요소 텍스트의 Range.getClientRects()[0].width
probeP   = 같은 font-size/weight로 font-family:'Pretendard Variable' 강제한 오프스크린 span 폭
probeSys = 같은 조건으로 font-family:'Malgun Gothic','맑은 고딕' 강제한 span 폭

판정:  |targetW − probeP| < 0.5   AND   |targetW − probeSys| > 1.0
```
**`probeSys`와의 차이를 요구하는 것이 핵심** — 폴백으로 그려지면 두 번째 조건이 깨진다.

**변이 검증(필수):** 같은 스크립트를 `page.route('**/fonts/**', r => r.abort())`로 다시 돌려 **동일 단언이 FAIL해야 한다.** 실패하지 않으면 검사가 무력하다는 뜻이므로 **스크립트 자체를 붉게 만든다.**

#### 검사 2 — 배율이 실제로 걸렸다 (B-4)
**항진 경로:** "font-size ≥ 13px"만 보면 원래 14px인 `text-sm` 요소 하나로 통과한다.
**설계:** 같은 `data-testid`의 **동일 요소**를 세 배율에서 측정해 **비**를 본다. 절대값이 아니라 비 + 요소 동일성을 DOM 경로로 고정. **요소를 못 찾으면 SKIP이 아니라 FAIL.**
**변이:** `--fs-scale`을 1로 강제 고정한 실행에서 FAIL해야 한다.

#### 검사 3 — 표 넘침 (C-1~C-3)
**항진 경로 3가지:**
1. 표가 화면에 없는데(닫힌 슬라이드 패널, 접힌 `<details>`) **0개를 검사하고 통과**
2. `clientWidth === 0`(`display:none`)이라 비교가 무의미
3. `overflow-x-auto`가 있어 넘쳐도 안 깨지므로 **넘침을 못 잡음**

**설계:**
- **검사한 표 개수를 단언한다** (`count >= 상수`) — 걸러진 개수도 리포트
- `clientWidth > 50`인 표만 센다
- 배율별 기대치를 **분리**한다 (md/lg 금지 · xl 허용 · `documentElement`는 전 배율 금지)
- rowtable에 `'99999'`를 **실제로 타이핑해 넣고** 재측정 — **빈 칸은 절대 안 넘친다**

**변이:** `--fs-scale: 2`를 강제 주입한 실행에서 C-1이 FAIL해야 한다.

#### 검사 4 — 인쇄 불변 (E-1, E-2)
**항진 경로:** `emulateMedia('print')`만 걸고 값을 안 비교하거나, **비교 기준을 "지금 값"으로 잡으면** 무엇을 해도 통과한다.
**설계:** 기준선을 **S0에서 뽑아 커밋한 고정 JSON**(`scripts/_fixtures/35-print-baseline.json`)으로 둔다. "지금 화면끼리" 비교하지 않는다. ⚠ 기준을 `HEAD:`로 잡으면 **커밋되는 순간 원문이 사라져 영구히 깨진다** — [[feedback_probe_baseline_pin]].
E-1은 PDF **소스 HTML sha256**을 비교한다(Gotenberg 왕복 없이 결정적). 배율 3종 모두.
**변이:** `@media print` 블록을 임시로 지운 빌드에서 E-2가 FAIL해야 한다.

#### 검사 5 — 코드모드 완전성 (B-3)
**항진 경로:** 파일 목록이 비면 0건이라 통과.
**설계:** **스캔한 파일 개수 = 16**을 함께 단언 + 각 파일에 `text-form-`이 **최소 1회** + **16파일 밖에서 `text-form-` 사용 0건**.
