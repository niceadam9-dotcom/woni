## 1. 배경

세부 제원(별지 9호 4~7쪽 "3. 소방시설등의 세부 현황" — 별지 4호 3~7쪽 공용)은 8개 섹션(s31~s38) × 40블록 × 약 250필드를 전부 수동 타이핑하는 구조다. 저장도 섹션당 [제원 저장] 버튼(최대 8회)이라 입력·저장 모두 클릭이 많다. 2026-08-05 사용자 확정 요구:

1. **기본값 원클릭 채우기** — 건물 데이터·1.4 층별 수량표에서 유도 가능한 필드 자동 입력
2. **층·동명 칩 선택** — 반복되는 동명·층 텍스트 필드를 클릭만으로 입력
3. **저장 최소화** — 섹션당 저장 8개 → [모두 저장] 1클릭 (미저장 섹션 일괄)
4. **숫자 필드 +/- 스테퍼** (2026-08-05 추가) — 소방계획서 본문·제원의 숫자 입력칸을 키보드 타이핑 없이 `[−][+]` 클릭으로 1씩 증감. 현장·모바일에서 수량(소화기·감지기·인원·계단 등)을 손쉽게 조정.

전제(같은 날 선행 확정): 1.4 소방시설은 자동 저장 폐지·최종 저장 + 이탈 가드(erp:plan-dirty), 설비 대장은 우측 슬라이드 패널로 이동.

### 2-4. 숫자 +/- 스테퍼 (2026-08-05 추가) — 공용 `NumField` 강화

**핵심 결정**: 본문 숫자 입력(**계단·경사로 개소**·피난용승강기 대·인원 명 등)은 이미 공용 컴포넌트 `NumField`(`erp/src/components/ui/fields.tsx`)를 쓰므로, **`NumField`에 스테퍼를 내장**하면 개소 필드에 즉시·일관 적용된다. 별도 컴포넌트 신설 없이 한 곳 수정으로 전 사용처 반영.

- **`NumField` 레이아웃 변경**: `[−] [input] [unit] [+]` — 입력칸 좌우에 `−`/`+` 버튼(28px 이상 터치 타깃). 기존 `inputCls`·`className`·`unit`·`id`·`decimal` prop 계약 유지.
- **증감 규칙**: 클릭 = 현재값 `± step`(기본 `step=1`). 하한 `min=0`(음수 금지, 개소·대·명은 자연수), 상한 없음(`max?` 옵션). 빈 값에서 `[+]`=`step`(=1), `[−]`=빈칸 유지(0 강제 안 함).
  - `decimal` 필드도 스테퍼 step은 정수 1 기본(소수는 직접 타이핑) — 유효수량 ㎥ 등은 큰 단위라 ± 1이 무의미하면 `step` override.
- **비활성**: `disabled` 시 버튼도 opacity·클릭 불가. 값 파싱(`onChange`의 `[^0-9.]` 필터)·저장 로직 불변 — 버튼은 같은 `onChange(String(next))`를 호출할 뿐.
- **선택적 끄기**: `stepper={false}`로 스테퍼 숨김(기존 순수 입력 필요 시). 기본 on.
- **적용 지점(파급)**:
  1. **1.1 일반현황** — 계단·경사로 **개소**, 피난용승강기, 근무·거주·최대 인원 (fire-plan-info-panel의 `NumField` 사용처 전부, 자동 반영)
  2. **1.4 층별 수량표** (plan-form14) — **행 확장 편집**(2026-08-06 확정). 6열(소화기·차동식·연기식·정온식·유도등·비상조명)×N행 밀집 표라 셀마다 ± 버튼을 넣으면 셀당 약 64px·총 약 384px이 늘어 레이아웃이 깨진다(가로 스크롤 래퍼도 없음). 따라서 **표는 그대로 두고** 층 셀의 `▶` 토글로 행 아래 편집 패널을 펼쳐 `라벨 + [−][값][+]` 6개를 넉넉히 배치. 표 직접 타이핑 병행 유지(§2-2 칩 규약과 동일), 값 갱신은 공용 `setFloorCount(row, col, raw)` 1곳. 0은 빈칸으로 표시하는 기존 표 규약(`counts[c] || ''`)을 그대로 따름 — 0에서 `[−]`는 무동작(음수 불가), 빈칸에서 `[+]`는 1. 행 삭제·건물 전환·층 자동 생성 시 인덱스 기준 펼침 상태 초기화.
  3. **설비 대장 제원** (plan-form14-specs `fieldWidget`) — **수량형 단위만 선별 적용**(2026-08-06 확정). 카탈로그 number 필드 47개의 단위 분포를 조사한 결과 수량형(개 12·구역 2·대·개층·개소 각 1 = 17개)만 ±1이 의미 있고, 용량·치수형(ℓ 6·m 5·ℓ/min 4·MPa 3·㎜ 3·㎥ 3·㎥/min 2·㎾ 2·㎡ 1·㎜Aq 1 = 30개)은 ±1이 무의미하므로 직접 입력 유지. `COUNT_UNITS` 집합으로 분기.
     - **`NumField`를 쓰지 않는다**: 제원 입력칸은 빈칸=앰버·자동채움=보라 링(`box`)으로 상태를 표시하는데, `NumField`는 내부 기본 클래스를 항상 앞세워 Tailwind 유틸이 충돌한다(원래 이 항목이 보류된 이유). 대신 증감 규칙만 공용 함수 **`bumpNumber(value, dir, opts)`**(fields.tsx, `NumField`도 이 함수를 사용)로 추출해 공유하고, 마크업은 `box`를 그대로 둔 채 좌우에 컴팩트 버튼(size-6)만 붙인다. 강조 링·높이(h-7)가 보존되고 증감 규칙은 한 곳에만 존재한다.
     - `box`에 `min-w-0` 추가 — ± 형제와 같은 flex 행에서 입력칸이 정상 축소되도록.
- 접근성: 버튼 `aria-label`(`${unit ?? ''} 1 증가` / `1 감소`), input `inputMode` 유지.
