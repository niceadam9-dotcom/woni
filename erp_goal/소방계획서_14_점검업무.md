## 1. 배경·요구

사용자 질의(2026-08-10): "별지9호에 소방시설등 점검결과(점검표)가 들어가는데, 이것을 점검업무 점검표, 1.4 소방시설 > 세부제원과 통합하고 싶다. **회차는 최종만 남기는 것으로** 제안해달라."

- 회차 히스토리를 ERP에 남기지 않는 방향은 소방계획서_14.md **#17**("소방계획서와 별지는 최신 내용만 남기고 나머지는 별도 인쇄해 종이 보관, ERP에서는 관리하지 않음")과 일치한다.
- 같은 문서의 **#12·#15·#18**(회차별작성조회에 점검표 트리·점검상세 입력을 조회에서·점검표입력 트리 조회와 동기화)도 전부 "점검표의 조회·입력 동선" 문제다 — 이 기안의 §4(T-2)가 세 항목을 **흡수·대체**한다. **"최종만 유지" 결정에 따라 회차별 트리는 만들지 않는다.**

## 2. 현재 구조 (2026-08-10 코드 실측)

### 2-1. 데이터는 이미 별지9호에서 합류한다 — 갈라진 것은 화면·동선

| 데이터 | 저장소 (귀속 축) | 입력 화면 | 별지9호 반영 |
|---|---|---|---|
| 점검 결과 O/X/N | `inspection_sheet_responses` (**점검 건**=inspection_id) | 점검 상세 `/inspections/[id]` — `inspection-sheet-client.tsx` | 3쪽 결과 롤업 + 8쪽 불량 (`assembleReport9`) |
| 설비 설치 여부 | `fire_facilities` (**건물**) | 고객 탭 1.4 본문 — `plan-form14.tsx` | 3쪽 설비 체크 |
| 세부제원(설비 대장) | `customer_facility_specs` (**고객·건물**) | 1.4 우측 패널 — `plan-form14-specs.tsx` | 4~7쪽 주입 |

즉 "점검표 결과가 세 곳에 따로 있다"가 아니라, **원본은 각각 한 곳씩인데 입력·조회 화면이 점검 상세(회차 축)와 고객 탭(고객 축)으로 갈라져 서로 상대 상태가 보이지 않는 것**이 실제 문제다. 세부제원 쪽에는 이미 부분 보완이 있다(9호發 진입·복귀 `from=report9`, 교차 검증 칩 `getInspectedFacilityCodesAction`).

### 2-2. 함께 드러난 기존 결함 — 별지9호 조립은 아직 퍼지 매칭을 쓴다

점검표 시트 ↔ 설비 매칭은 퍼지 매칭의 실측 결함(오검: 스프링클러→간이스프링클러 / 누락: 시각경보기↔시각경보장치, 2026-07-25 별그리다) 때문에 명시 매핑(`sheet-facility-map.ts` `SHEET_FACILITY_MAP`)으로 교체됐다. 그런데 이 명시 매핑은 **빠른 입력·교차 검증에만** 쓰이고, 정작 **별지9호 조립(`assembleReport9`)의 3쪽 결과 롤업·8쪽 그룹 판정은 여전히 자체 퍼지 `nameMatch`**(공백 제거 양방향 includes)로 시트명↔`FORM3_ITEMS`를 잇는다. 같은 결함 계열이 문서 생성 경로에 남아 있는 셈이다. → §5(T-3)

## 3. 결정사항 (2026-08-10 사용자 확정)

1. **회차(히스토리) 축을 화면에서 제거한다 — ERP의 점검표는 "최종(최신) 상태" 1벌.** 과거 회차의 공식 보관본은 이미 생성된 별지9호 PDF(보관함)와 종이 보관(#17)이 담당한다.
2. 통합 대상 3축(별지9호 · 점검업무 점검표 · 1.4 세부제원)은 **저장소를 합치지 않는다** — 점검 결과는 점검 건 귀속, 제원은 고객·건물 귀속이라는 축 구분은 데이터 정합의 근거이므로 유지하고, **화면과 어휘를 통합**한다.

## 4. 제안 T-1·T-2 — 최신 단일 상태 + 고객 탭 합류

### T-1. 최신 단일 상태 원칙 (스키마 무변경)

- "현재 점검표" = **최신 특별점검 건의 응답**으로 서버가 단일 결정한다. 공용 헬퍼 `getLatestSpecialInspection(customerId)` 신설(서버 전용).

  **판정 규칙 (2026-08-10 Q-3 확정)**
  ```
  where  plan_type is null OR plan_type like 'special_%'   -- 레거시 null 포함
  order by year desc, sequence_num desc                    -- 기존 선례와 통일
  limit 1                                                  -- 취소 조건 없음
  ```
  > **정정 이력** — 초안은 "취소되지 않은 건 중 `inspection_start_date` 최신 1건"이었으나 독립 검증에서 두 가지가 걸렸고, 사용자 확정으로 위와 같이 정리됐다.
  > - **C-1 (해소·조건 삭제)**: `InspectionStatus`에 `cancelled`가 **없다**(`scheduled | in_progress | completed | overdue`, `types/index.ts:28`). 취소 개념은 `inspection_plan_items.status`·`PlanStatus`에만 있다(`:34-35`). → **'미취소' 조건을 뺀다.** plan_items 조인을 하지 않으며, 기존 선례도 취소를 보지 않으므로 동작이 일치한다.
  > - **C-2 (해소·선례 통일)**: 같은 목적의 기존 구현 `getInspectedFacilityCodesAction`이 `year desc, sequence_num desc`로 정렬한다(`facility-spec-actions.ts:136-150`). → **정렬 축을 그쪽으로 통일**하고, 그 로컬 로직을 신설 헬퍼로 흡수해 **교차 검증 칩도 같은 헬퍼를 쓰게 한다**(두 화면이 다른 회차를 가리킬 여지를 구조적으로 제거).
- **화면 어디에도 회차 선택 UI를 두지 않는다.** 점검 상세는 지금처럼 그 건의 점검표를 편집하고, 고객 탭(§T-2)은 항상 최신 건에 바인딩된다 — 저장소가 하나이므로 두 진입점의 "동기화"는 자동이다(같은 행을 읽고 쓴다).
- **[이전 결과 이어받기]** — 새 점검 건에 응답이 0건이고 직전 특별점검 건에 응답이 있으면, 점검표 화면 상단에 버튼을 노출한다. 클릭 시 직전 건 응답을 새 건으로 복사(`carryOverSheetResponsesAction(inspectionId)`, 미입력 항목만·확인창 필수).
  - **자동 이월은 하지 않는다** — 점검하지 않은 항목이 ○로 미리 채워져 있으면 "점검 없이 통과" 기록 위조가 된다. 절충안(N=해당없음 판정만 자동 이월 — 설비 구성이 불변이므로 위조 위험 없음)은 선택지로 병기하며, 채택 여부는 사용자 결정 사항(§7 Q-1).
- 과거 회차 응답 행은 **DB에 자연 보존하되 UI에 노출하지 않는다.** 삭제 배치는 만들지 않는다 — 생성된 과거 별지9호 PDF와의 대사(監査) 근거가 되고, 지워서 얻는 것이 없다.

| T-2a | **세부제원 패널 섹션 헤더에 최신 점검 결과 배지** — 설비별 ○(전항목 양호)/×(불량 있음)/／(해당없음)/미입력 + 불량 수, 읽기 전용. 클릭 시 T-2b 노드의 해당 시트로 이동 | 롤업 로직은 `assembleReport9`의 시트 통계(sheetStat)를 공용 함수로 추출해 공유. 교차 검증 칩(`getInspectedFacilityCodesAction`) 확장 |

## 5. 제안 T-3·T-4 — 어휘 단일화·생성 경로

### T-3. 별지9호 조립의 퍼지 매칭 제거 (§2-2 결함 해소)

- `sheet-facility-map.ts`에 **`FORM3_SHEET_MAP`**(별지9호 3쪽 `FORM3_ITEMS` 40항목 ↔ 점검표 시트명) 명시 매핑 상수를 추가하고, `assembleReport9`의 3쪽 결과 롤업(resultMarks)·8쪽 그룹 판정(groupOfCode)의 `nameMatch` 퍼지 호출을 이것으로 교체한다. 미등재 항목만 종전 퍼지 폴백(기존 `SHEET_FACILITY_MAP` 관례 동일).
- 검증: 교체 전후 동일 점검 건으로 조립 결과(resultMarks·defectRows) 스냅샷 비교 프로브 — 차이가 나는 항목은 전부 퍼지 결함(오검·누락) 교정분인지 수동 확인 후 기록.

### T-4. 별지9호 생성은 현행 유지 — "점검표 현황이 별지9호에 기록되는가" 재점검 완료 (2026-08-10)

이미 해당 점검 건(=최신) 기준으로 생성하므로 변경 없음. "회차 선택 없음" 원칙만 확인 기록. 세부제원(4~7쪽)·설치(3쪽 체크)도 기존 조립 경로 그대로.

사용자 재확인 요청("별지9호에 점검표 현황이 기록되어야 합니다")에 대한 실측:
