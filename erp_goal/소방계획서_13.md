## 1. 발단

사용자 요청: "1.3에서 관할소방서가 선택되면 거리·도착예상이 자동완성되게 해달라."

착수 전 코드 확인에서 **자동완성이 원리적으로 불가능한 상태**임이 드러났다 — 아래 K-1~K-3이 먼저 해결돼야 했다.

## 2. 진단

### K-1 (차단급) 1.3에서 고른 소방서가 경로 조회에 반영되지 않는다

`fire-route-actions.ts`의 `resolveStationCoords`는 `customers.fire_station`(고객 정보 자동 지정값)만 읽었다.
1.3 드롭다운은 `sections.location.fireStation`에만 저장된다 → **1.3에서 "홍천소방서"를 골라도 경로는 "양평소방서" 기준**으로 나왔다.

### K-2 경로 캐시에 소방서 축이 없다

`sections.routeMeta`는 고객당 단일 슬롯이라, 소방서를 바꿔도 `cached: true`로 옛 경로가 반환됐다.
[다시 가져오기]를 눌러야만 갱신되는데, 사용자는 소방서를 바꿨으니 새 값이라고 믿는다.

### K-3 119안전센터 라벨은 좌표 조회에서 반드시 실패한다

드롭다운은 `"양평소방서 (용문119안전센터)"` 라벨을 만드는데(`fire-station.ts:117`),
좌표 조회는 이 문자열을 `region_fire_stations.fire_station`과 그대로 `.eq()` 비교한다 → 매칭 불가.
`fire_station_centers`(117)에는 주소·좌표 컬럼 자체가 없다.
**K-1을 고치는 순간 이 경로가 활성화되어 바로 터진다.**

### K-4 값의 출처·신선도를 화면이 말하지 않는다

소방서를 바꿔도 기존 거리·도착예상은 **다른 소방서 기준의 낡은 값**인 채 남아 그대로 인쇄된다.

## 3. 설계 (A안)

### A-1 — 경로 조회 출발지를 1.3 선택값으로

`getFireRouteAction(customerId, { station })` 파라미터 추가.
`resolveStationLabel(customerId, preferred)`이 **1.3 선택값 → 고객 정보 → 주소 추정** 순으로 라벨을 확정한다.
클라이언트가 넘기는 값은 `loc.fireStation.trim() || autoFireStation.trim()` — **인쇄 규약(`fire-plan-template.ts:240`)과 동일한 우선순위**다.

### A-2 — 소방서 확정 시 자동 조회 → 거리·도착예상 기입

- **select**: `onChange` 즉시 조회
- **직접 입력(text)**: 타이핑마다 조회하면 API를 낭비하므로 `onBlur` 1회
- 반영 규약(기존 §9-6 "조용히 덮어쓰지 않는다"와 일관):
  - 거리·ETA가 **둘 다 비어 있으면** 조용히 채운다
  - **값이 있고 조회 결과와 다르면** 덮어쓰지 않고 `⚠ … [조회 값으로 적용]` 제안만
  - 값이 같으면 확인 메시지만
- 조회 결과는 `route` state에도 넣어 **아래 [서술 초안]·[경로도 초안]이 재조회 없이 같은 결과를 쓴다**

### A-3 — 캐시에 소방서 축 추가

`RouteMeta.station`(요청 라벨) 기록. 캐시 유효 조건 = `(cached.station ?? cached.stationName) === label`.
구 캐시는 `station`이 없어 `stationName`으로 판정한다(하위호환).
`generateRouteImageAction`도 같은 축을 써서 **다른 소방서 캐시로 경로도를 만들지 않는다**.

이 축이 A-2의 자동 조회가 유료 API(Directions)를 반복 호출하지 않게 막는 안전장치다 —
같은 소방서를 다시 고르면 캐시 히트로 끝난다.

### A-4(부분) — 119안전센터 라벨 환원 + 표기

`stationBaseName("양평소방서 (용문119안전센터)") → "양평소방서"`로 환원해 본서 좌표로 계산하고,
`centerFallback` 플래그를 반환해 **화면에 "선택한 119안전센터는 좌표 미보유라 본서 기준입니다"를 표기**한다.
서술 초안도 본서명으로 만든다(센터명으로 쓰면 거짓 문장이 된다).

> 센터 좌표를 실제로 갖추는 일(마이그레이션 118 + 시드)은 **보류** — §5 참조.

### A-5 — 낡은 값 경고

조회 결과가 기존 입력과 다르면 `⚠ 현재 거리·도착예상(…)은 ○○ 기준 조회 결과(…)와 다릅니다 — 다른 소방서 기준의 값일 수 있습니다`.

## 5. 잔여 리스크

- **실출동은 119안전센터에서 나간다.** 센터를 골라도 거리·ETA는 본서 기준이라 실제보다 멀게 나올 수 있다. 화면에 표기는 하지만 값 자체의 정확도 문제는 A-4 완전판 전까지 남는다.
- 소방서 값이 `customers.fire_station`과 `sections.location.fireStation`으로 **이원화**된 상태는 그대로다(D-2 보류). 경로 조회는 A-1로 1.3 값을 따르게 됐지만, 별지·보고서 계열은 여전히 고객 값을 쓰는 경로가 있다.
