# 소방계획서 하위 탭 상세 설계 (4차) — 서브탭 방식

> 2026-07-21. `소방계획서_3.md`(아코디언안)를 **서브탭 방식**으로 재설계.
> "탭" = 고객관리 상위 탭(기본정보·건물·시설·관계인…)과 같은 형태의 탭 줄을 **소방계획서 탭 안에 한 줄 더** 두는 구조.
> 유지 원칙: **기본정보 탭 그대로 유지 · 건물·시설 탭의 건물목록 그대로 유지** (소방시설현황만 소방계획서로 이동)

---

## 1. 상위 탭 구조 (변경 최소화)

```
고객 상세
┌──────────────────────────────────────────────────────────────┐
│ [기본정보] [건물] [관계인] [소방계획서 14/17⚠] [청구·수금] [이력] │  ← 상위 탭 (기존 그대로)
└──────────────────────────────────────────────────────────────┘
```

| 상위 탭 | 변경 여부 | 내용 |
|---|---|---|
| 기본정보 | **유지** | 현행 그대로 (주소·점검유형·기준일·담당 등) |
| 건물| **부분 변경** | **건물목록(건물 추가·주소·면적·층수) 유지**. 하단의 "소방시설현황" 패널만 소방계획서 > 소방시설 서브탭으로 이동 |
| 관계인 | 유지 | 현행 그대로 |
| **소방계획서** | **재편** | 아래 §2 서브탭 구조로 전면 재편 (기존: 보관함 + 계획서정보 아코디언 + 생성 모달) |
| 청구·수금 / 이력 | 유지 | 현행 그대로 |

- 같은 데이터(주소·급수·구조 등)는 기본정보/건물·시설 탭과 소방계획서 서브탭 **양쪽에서 편집 가능** — 저장소가 동일(customers/buildings)하므로 충돌 없음. 소방계획서 쪽은 "한글 서식 순서" 관점의 편집 화면일 뿐이다.
**양쪽에서 조회/편집 만들지 말고, 한쪽만 조회/편집 있을 뿐입니다. 즉 양쪽이 처음부터 없도록 중복이 없도록 해줘.

## 2. 소방계획서 탭 내부 — 서브탭 줄 + 공통 생성 바

```
소방계획서 탭 선택 시:
┌──────────────────────────────────────────────────────────────┐
│ 준비율 ▓▓▓▓▓▓░░ 14/17 · 누락: 1.5 미입력, 최초점검 미기재        │
│                     [📄 HWP 생성]  [🖨 PDF 생성]  [⬇ 데이터 시트] │  ← 생성 바 (모든 서브탭 상단 고정)
├──────────────────────────────────────────────────────────────┤
│ [보관함(3)] [일반현황✓] [세부현황 2/4] [소방시설✓] [피난·방화 ⚠]   │
│ [기타시설 ⚠] [선임·자위대 1/2] [자체점검 1/3] [훈련·교육 ⚠] [사진(1)]│  ← 서브탭 (2줄 허용·모바일 가로 스크롤)
├──────────────────────────────────────────────────────────────┤
│                                                              │
│              (선택된 서브탭 내용 — §3 상세)                       │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

- **서브탭 10개** (한글 서식 순서). 기본 진입 = **보관함**(현행 진입 경험 유지 — 인쇄·다운로드가 최다 사용), 보관함 대신 소방계획서 개정이력 대체해줘 개정이력 옆에 hwp 다운로드 아이콘

- URL: `/customers/{id}?tab=plan&sub=facility` — 서브탭도 URL로 직접 진입 가능(누락 안내 링크에서 활용).
- 뱃지: ✓(완료) · `n/m`(부분) · ⚠(미입력) · `(n)`(건수) — 준비율 게이지는 서브탭 뱃지의 합산.
- 생성 바는 서브탭과 무관하게 항상 표시. 생성 버튼은 **저장된 데이터로 즉시 실행**(기존 모달 폐지). 누락이 있으면 버튼 옆 요약 + 확인 후 진행(빈 칸 출력 허용 원칙 유지) 개정이력 기반으로 선택하여 생성됨.
- 컴포넌트: 상위 `CustomerTabs` 패턴을 소형화한 `PlanSubTabs` 재사용 제작. 각 서브탭 내용은 독립 컴포넌트(개별 저장).

## 4. 공통 동작 규칙

1. **저장**: 서브탭별 [저장] 버튼 + 미저장 변경 시 서브탭 이동에 확인 알림. 저장 대상은 섹션별로 정규 테이블 또는 `fire_plan_forms.sections.{key}`(096 신설, `소방계획서_3.md` §3 동일).
2. **생성**: 생성 바 버튼 → `assembleFirePlanGenData(customerId)` 어댑터가 정규 테이블+JSONB를 조립해 기존 파이프라인(웹 PDF / HWP 워커 2단계 등록) 실행. `.form.json` 스냅샷 보존.
3. **자동 채움 우선순위**: 고객 데이터 > 프리셋 > 양식 기본값 (현행 유지).
4. **기존 고객 호환**: fire_plan_forms 비어 있고 최신 `.form.json` 존재 시 "이전 입력 가져오기" 1회 임포트 배너.
5. **누락 안내**: 생성 결과의 누락 라벨 → 해당 서브탭 딥링크(`?tab=plan&sub=…`)로 연결.
6. **모바일**: 서브탭 가로 스크롤, 표 입력은 카드형 폴백.
