## 2. 현행 진단 — 왜 바꾸나

1. **수동 대장 불러오기의 마찰**: 주소는 건물·시설 탭에서 넣지만, 소방계획서용 확장 필드(건축허가일·건축면적·세대수·동수·승강기·주차장·구조·지붕·높이 등 `LEDGER_FIELDS`)는 소방계획서 탭에서 [건축물대장 불러오기]를 **따로 눌러야** 채워졌다. 주소를 넣었는데 값이 비어 보이는 혼동.
2. **모드 전환의 인지 비용**: 소방계획서(빠른입력↔서식전체), 기본정보(요약↔편집), 1.1 계획서 정보(요약↔편집+아코디언) — 화면마다 "지금 어느 모드지", "편집하려면 버튼을 눌러야 하나"를 계속 판단해야 했다. 인라인 편집이 들어오면서 [편집] 버튼의 고유 역할도 좁아진 상태.
3. **좁은 작업 폭**: 고객 상세 탭 전체가 `max-w-3xl`(768px)로 묶여 있고 우측 요약 패널이 폭을 더 뺏어, 서식 폼이 답답하게 갇혔다.
4. **발견성 저하**: "요약 값을 클릭하면 편집된다"를 모르는 사용자에겐 편집 진입 자체가 숨겨져 있었다.

→ 방향: **"모드를 없애고 항상 보이고 항상 편집" + 대장 자동화 + 화면 확장**. 소방계획서_8의 트리 단일 허브(D-4·D-12)를 입력 동선 전반으로 확장한다.

## 3. 변경 내역

### 3-1. 건축물대장 주소 확정 시 자동 반영 (D-1·2·3)
- **`autoApplyLedgerEmptyAction`** 신규 (`fire-plan-info-actions.ts`) — 활성 건물의 bcode·지번(없으면 저장된 주소로 Juso 지오코딩 후 백필, B안)으로 대장 조회 → `LEDGER_FIELDS` 중 **비어있는 칸만** 저장. 리다이렉트 없는 권한 체크(best-effort), 재조회 방지용 `ledger_synced_at` 항상 기록.
- **트리거 ①**: 건물·시설 탭 저장 직후 bcode가 있으면 자동 호출 (`building-inline-panel.tsx`).
- **트리거 ②**: 소방계획서 탭 진입 시 `ledgerAutoNeeded`(활성 건물이 미동기화이고 주소 보유)면 마운트 1회 자동 조회·반영 (`plan-tab-view.tsx` + `[id]/page.tsx`).
- 기존 [건축물대장 불러오기] 버튼은 **강제 재조회·덮어쓰기 미리보기** 용도로 유지.

### 3-2. 소방계획서 서식 전체 기본화 + 전체 폭 (D-4·5·6)
- `plan-tab-view.tsx` — `mode`(quick/full) 상태·토글 버튼 폐기. **서식 전체 트리가 항상 기본 화면**.
- 트리 최상단에 **`⚡ 빠른 입력` 노드**(랜딩 기본) 신설. 기존 빠른 입력 콘텐츠(필수 완성도·필요문서 칩·건축물대장 불러오기·누락 칩·**자체점검 송달 동의**·보관함 요약)를 `quickPanel`로 묶어 이 노드에 **한 페이지**로 표시.
- `customer-tabs.tsx` — `summary`·`fullWidthKeys` prop 추가. `fullWidthKeys=['plan']` 탭이 활성이면 `max-w-3xl` 해제 + 요약 패널 접힘. `[id]/page.tsx`는 요약 패널을 `summary` prop으로 이관.

### 3-3. 기본정보 탭 — 요약/편집 통합, 항상 편집 (D-7·9)
- `edit-customer-info-client.tsx` 재작성 — `mode`(summary/edit)·[편집]·[요약 보기] 버튼·요약 전용 인라인 퀵 입력(quick·saveQuick·openEdit) 폐기.
- **2~3열 촘촘 그리드**에 전 필드 상시 표시·수정: 점검유형/점검계획일*/고객명*/계약일/사용승인일/관할소방서/점검료(읽기)/주소(전체 폭)/비고(전체 폭).
- 보존: 저장/취소는 isDirty 시에만, 점검계획일 확정 일정 전파 팝업, 전체 검증, **주소 검색 = 선택 즉시 저장+전파**(`quickAddressApplyAction` — 관할소방서 자동 매핑·건물 주소·bcode). 도로명 수기 보정은 [저장]으로.
- 이로써 이전에 [편집] 버튼만이 하던 ①고객명 ②주소 세부 수기 ③일괄 수정이 전부 상시 편집으로 흡수됨.

### 3-4. 1.1 계획서 정보 패널 — 항상 편집, 아코디언 폐기 (D-8·9)
- `fire-plan-info-panel.tsx` 재작성 — `mode`(summary/edit)·`open`(아코디언) 상태 폐기, [편집]·[요약 보기] 버튼·요약 그리드 블록 삭제.
- 열자마자 **①시설현황 ②운영현황 ③화재보험 + 자위소방대 편집 폼**이 바로 노출.
- **헤더의 준비율 게이지 + 누락 칩은 유지** → 요약 그리드가 하던 "값 스캔·누락 확인" 역할을 대신(1.1은 이미 헤더에 준비율이 상시 표시돼 실손실 작음).
- 도구(추천값 채우기·다른 고객에서 복사)는 상단 툴바에 유지. `focusMissing`·추천/복사·save의 `setMode` 참조 정리(항상 편집이라 모드 전환 불필요).
