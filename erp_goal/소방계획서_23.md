## 2. 진단

### P-1. 중분류(머더) 이름이 DB에 없다 — **확정**

`scripts/seed-inspection-sheets.mjs:13`이 코드 정규식 `^\d{1,2}-[A-Z]-\d{1,3}$`만 잡고, `:32-42` 루프가 그 정규식에 맞는 행만 항목으로 취한다. 원본 엑셀에 함께 있는 **`1-A. 소화기구(소화기, 자동확산소화기, 간이소화용구)` 같은 중분류 제목 행은 정규식에 안 맞아 버려진다.**

`:76`의 `facility_type: f.name`은 **설비명(= `sheet_name`과 동일)** 이라 중분류 라벨로 못 쓴다 — 한 시트의 모든 항목이 같은 값이다.

결과적으로 `lib/sheet-scope.ts:32-35`가 코드 접두로 폴백한다:

```ts
export function sheetItemGroup(itemCode: string, facilityType: string | null): string {
  const byCode = itemCode.replace(/-\d+$/, '')                  // '1-A-001' → '1-A'
  return /^[A-Z]/.test(itemCode) ? (facilityType ?? byCode) : byCode
}
```
`1-A-001`은 숫자로 시작하므로 `byCode` 분기 → 화면 헤더가 **`1-A`**.

### P-2. 세부항목 입력 영역이 좁다 — **확정**

`inspection-sheet-client.tsx:319`가 설비 목록을 `w-36` 레일로 접고, `sheet-item-editor.tsx:32`의 기본 `maxHeight = 'max-h-[420px]'` 스크롤 박스에 항목이 들어간다. STD 시트는 한 장에 수십~90여 항목이다(예: 스프링클러 90).
