## 1. 배경

별지 서식 "회차별 작성·조회"(고객 상세 > 소방계획서 탭 > 📑 별지 서식)는 소방계획서_8 H-2·H-3·H-5로 도입된 뒤 소방계획서_16(점검표 인라인 트리)·소방계획서_18(인쇄 번들·과거본 정리)이 얹히며 회차 카드 하나에 기능이 계속 누적됐다. 사용자 불만 3가지:

1. **정리** — 화면이 어수선하다
2. **속도** — 페이지·회차 열기가 느리다
3. **입력** — 점검표 조회·입력이 어렵다

## 2. 진단 (2026-08-11, 파일:라인 근거)

### 2-1. 속도 — 서버 왕복이 회차 수에 비례

- 마운트: `getCustomerRoundsAction`(reports/docs-actions.ts)이 inspections(limit 24)·plan_items(limit 48) 조회 후 **회차마다** `buildInspectionDocs` = storage.list(파일 100개 스캔) + inspection_defects + sheet_responses(count) 3쿼리를 병렬 실행 → **왕복 3+3N**. 원격 Supabase 왕복 ~240ms 전제(customers/[id]/page.tsx 상단 2026-08-11 성능 주석)에서 회차 8건이면 마운트에만 5초+.
- 회차 펼침: `prefetchPreviews`(plan-annex-section.tsx:108)가 별지 4종(`getAnnexPreviewHtmlAction` × report4/9/10/11)을 일괄 프리페치 — 각 호출이 서버에서 다중 쿼리 조립 → 12~20왕복.
- 생성/업로드 후: `reload()` + `setPreviewCache({})`(plan-annex-section.tsx:91) — **캐시 전체 폐기**라 방금 생성한 문서 재열람도 3~5초.

### 2-2. 정리 — 한 카드에 전부

- plan-annex-section.tsx ~500줄: 회차 아코디언 + 문서 행 6종(InspectionDocRows) + 점검표 트리 + 호버 퀵뷰 + 전체 미리보기 모달 + 점검일 확정 모달 혼재.
- 완료 회차가 진행 중·예정과 한 목록에 나열 — 연차가 쌓일수록 목록이 길어진다.

### 2-3. 입력 — 수동 저장·기능 비대칭

- 점검표: 설비별 [이 설비 저장] 각각 클릭(설비 10개면 저장 10클릭). 공용 입력기 `SheetItemEditor`(inspections/sheet-item-editor.tsx)의 O/X/N 버튼이 28px로 현장 터치에 작다.
- **기능 비대칭**: 점검 상세(inspection-sheet-client.tsx)에는 [설치 설비 전체 양호 ○](`bulkAllGoodAction`, sheet-actions.ts:114 — 미입력만 채움·기존값 보존)과 불량 검색 태깅(`searchQuickItemsAction`, §9-4 A안)이 있는데, **회차별 작성·조회 트리에는 없다**. 대부분 양호·불량 소수인 현장 패턴에서 입력 시간이 항목 수 비례로 걸린다.

## 4. 설계

### S1 — 부분 갱신 (저위험 선행, 커밋 C1)

- `reports/docs-actions.ts`: 신규 `getRoundDocsAction(customerId, inspectionId)` — `buildInspectionDocs` 1건 노출(왕복 ~4).
- `plan-annex-section.tsx`: `refreshRound(inspectionId)` — 해당 회차 docs만 패치 + 미리보기 캐시 그 회차 키만 무효화. `generate()`·`upload()`·`AnnexComposePanel onGenerated`의 `reload()`를 교체. `runStart()`의 `reload()`는 유지(회차 집합 자체가 바뀜).
- 효과: 생성·업로드 직후 3~5초 → 1초 미만, 다른 펼친 회차 iframe 재렌더 제거.

### S2 — 마운트 왕복 상수화 + 지난 회차 접힘 (커밋 C2)

- `getCustomerRoundsAction` 재편: **활성 회차**(state≠completed)만 `buildInspectionDocs` 실행. **완료 회차**는 `docs: null` + `docsLite`(신규): 문서 존재 = gen_jobs 1쿼리(Q-4), 불량 수 = inspection_defects 전 회차 1쿼리 집계, cert = `findArchivedCertInspections` 기존 1쿼리. 왕복 **3+3N → 6~7 고정**(회차 8건 ~5초 → ~1.5초).
- UI: `active`/`past` 분리 — 활성은 기존 카드(최신 자동 펼침 유지), 완료는 "지난 회차 N건" 기본 접힘(연도별 그룹, 요약 행 `④✓ ⑨✓ … 불량 2 · 완료 05-10`). 요약 행 클릭 → `getRoundDocsAction` lazy 상세 → 기존 카드 본문 렌더. 18 세션 기능(hasBundlePdf·[전체 인쇄]·cert 칩)은 **조건 렌더 위치만 이동, 로직 이동 금지**.
- 경계: planned인데 과거 연도(방치 회차)는 완료가 아니므로 활성 카드에 남긴다.

### S4 — 점검표 입력 편의 (커밋 C4, Q-3·Q-5·Q-6 반영)

- **S4-1 자동 저장**: 신규 훅 `hooks/use-debounced-autosave.ts`(`{status, flush, pause/resume}`, 입력 멈춤 ~1초 후 saveFn(delta), 실행 중 변경은 대기열). plan-annex-sheet-tree.tsx는 **변경분(delta)만 upsert**(현행은 전체 전송 — 페이로드·Realtime 에코 감소), 저장 성공 시 baseline 병합 + 요약 로컬 패치(재조회는 시트 닫기·Realtime 이벤트 시로 한정), 머리줄에 `저장 중… / ✓ 저장됨 / ⚠ 저장 실패 — [다시 시도]` 칩, 이탈 시 flush.
- **S4-2 Realtime 상호작용**: stale(원격 변경+dirty) 시 자동 저장 **pause** — 배너에 기존 [최신 불러오기] + 신규 [내 입력 저장](flush 후 remoteRefresh) 2택, 해소 후 resume.
  - **구현 시 변경 — ✕는 자동 저장 대상에서 제외**: X를 누르면 인라인 메모 + [등록](불량내역 자동 등록)이라는 별도 흐름이 시작된다. 여기서 미리 저장하면 메모 없는 X를 썼다가 곧바로 덮어쓰는 **이중 쓰기**가 되고 Realtime 에코도 두 번 난다. 부수 효과로 S5-5 배너가 검증 가능한 dirty 창도 보존된다. 남은 ✕는 시트를 닫을 때 `flush`가 함께 저장한다.
  - **구현 중 발견한 회귀**: `dirtyRef.current = ...`를 렌더 중에 쓰던 기존 코드(소방계획서_16 S5)가 React Compiler 메모이제이션과 얽혀 **dirty 판정이 낡아 원격 변경 배너가 뜨지 않았다**. effect 동기화로 교체(해당 파일 lint도 클린화).
- **S4-3 [이 설비 저장] 제거**(Q-5): `SheetItemEditor`에 `hideSave` prop — 트리는 숨기고 [닫기]만, 점검 상세는 종전 유지(이번 범위 밖).
- **S4-4 전체 양호→예외만 트리 이식**(Q-6①): 트리 머리줄에 [설치 설비 전체 양호 ○] + 불량 검색 태깅 추가 — `bulkAllGoodAction`·`searchQuickItemsAction`·`createDefectsFromXAction` **기존 액션 재사용, 호출부만 추가**(이중 구현 금지 규약 준수). 확인 다이얼로그는 점검 상세와 동일 문구.
- **S4-5 터치 버튼 확대**(Q-6②): O/X/N 버튼 28px → 40px+, 모바일에서 항목 행 간격·메모 필드 폭 보정(CSS 수준, 두 입력 경로 공용이라 점검 상세도 함께 개선됨).
- **S4-6 이전 회차 결과 복사**(Q-6③): [지난 회차 결과 불러오기] 신규 액션 — 같은 고객의 직전 완료 회차 responses를 **미입력 항목에만** 복사(기존값 절대 보존, bulkAllGoodAction과 같은 보존 규약). **안전장치(필수)**: ① 확인 다이얼로그에 "실제 점검을 대체할 수 없습니다 — 복사 후 현장 확인 결과로 수정하세요" 고지 ② 복사 직후 해당 시트 자동 펼침으로 검토 유도 ③ **X(불량) 응답은 복사해도 불량 내역 자동 등록은 하지 않음**(검토 후 수동 등록) ④ 감사: 복사 실행을 activity_logs에 기록. 리스크는 §6-6.
  - **구현 결과**: ①③④는 완료(③④는 프로브로 검증, ①③은 서버에도 강제). **②는 미구현** — 현재는 안내 문구로만 검토를 유도한다(§7 잔여).
